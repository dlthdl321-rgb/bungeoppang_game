# 보조 진행 시스템

## 범위와 공개 근거

2026-09-29의 보조 진행 구현이다. 기존 홈·스킬 경제·레벨 미션을 유지하고 일일 미션, 재고와 시간제 아이템, 별도 보상 코인과 상점, 최종 모의 교환을 연결했다. 이전 단계 문서는 당시 상태를 기록하며, 황금버터 모의 입력과 별사탕 상점은 이번 단계에서 실제 로컬 재고 사용과 코인 상점으로 바뀌었다.

공개 후기 [세종라이프 로그](https://dailysejong.tistory.com/entry/당근마켓-붕어빵게임-공략-총정리레벨-10-달성), [cITy & ETC](https://citynetc.tistory.com/290)에서 아이템 이름·초대 관련 흐름·황금버터 사용 미션을 참고했다. 이 자료만으로 정확한 효과·지속 시간·가격·일일 목표를 확정하지 않았다. 신규 보조 진행 밸런스는 전부 `estimated`이며 실제 원작 수치라는 의미가 아니다. 원본 에셋이나 비공개 API는 사용하지 않는다.

## 규칙

설정은 `lib/support_config.dart`, 평가는 `support_rules.dart`, 저장 모델은 `support_state.dart`로 분리했다. 금액·아이템 수량·진행량·배율의 재화 계산은 BigInt다.

| 일일 미션 | 추정 목표 | 개별 코인 |
| --- | --- | --- |
| 붕어빵 탭 | 50회 | 2 |
| 접속 중 생산 | 1,000개 | 3 |
| 스킬 구매 | 수량 3개 | 2 |
| 기본 초당 생산 | 10개 | 3 |

- 홈 왼쪽 위 일일 미션 버튼으로 진입한다. 진행률·수령 상태·자정까지 시간·미수령 보상 소멸 안내를 표시한다.
- 한국 시각(고정 UTC+9) 00:00 초기화한다. 기기 타임존과 무관하다. 시계가 뒤로 가도 이전 날짜를 다시 열지 않는다. 자정을 넘긴 이전 버튼은 수령을 거절한다.
- 생산량은 접속 중 클릭/자동 생산을 합산한다. 기본 설정에서 미접속 보상은 제외한다. `dailyOfflineCounts`로 교체할 수 있다.
- 스킬 구매는 버튼 횟수가 아니라 성공한 실제 구매 수량이다. 초당 목표는 그날 관찰한 기본 스킬 생산율 최대치다. 요정 배율은 목표를 대신 충족하지 않는다.
- 전체 목표 달성 보상은 코인 5 + 요정 1 + 황금버터 1이다. 개별 수령과 독립적이며 각각 하루 한 번이다. 전체 보상을 먼저 받아도 개별 보상을 받을 수 있다.

| 아이템 | 추정 효과 | 시간 | 코인 가격 | 최초 재고 |
| --- | --- | --- | --- | --- |
| 요정 | 자동 생산 2배 | 300초 | 3 | 1 |
| 황금버터 | 클릭 생산 2배 | 60초 | 2 | 1 |

- 수량·사용 횟수·효과 채널/배율·UTC 시작/종료·저장 시점 남은 밀리초를 보존한다. 활성 효과는 사용 당시 설정을 저장하므로 설정 변경 시 소급 변경하지 않는다.
- 사용 시 확인창에서 소비 수량, 현재/사용 후 생산, 시간을 보여 준다. 활성 중 같은 아이템은 추가 소비하지 않는다. 서로 다른 두 효과는 함께 적용된다. 미접속 중에도 시간이 흐른다.
- 황금버터 사용은 실제 보유 수량을 소비한다. 사용 시점에 황금버터 레벨 미션이 활성인 경우에만 그 미션을 올린다. 다음 단계에 과거 사용을 넘기지 않는다.
- 신규 지급/마이그레이션 최초 재고는 각 1개다. 이는 원작 확인값이 아닌 시제품 설정이다. 이번 단계에서 실제 초대 검증이나 초대별 아이템 지급은 추가하지 않았다.

## 코인·거래·교환

- 붕어빵과 분리된 `support.coins` 잔액이다. 레벨 보상(기존 설정 3개)과 일일 보상으로 획득한다.
- 모든 코인 증감에 ID·부호 있는 BigInt 금액·사유·TimeService UTC 시각을 기록한다. ID 예: `level:2`, `daily:2026-09-29:taps`, `shop:0`, `skin:cocoa`, `final:prototype-v1`.
- 잔액과 원장 합계를 검증하며 음수 잔액·중복 ID·수령 기록의 원장 누락은 손상으로 거부한다. 중복/잔액 부족 구매, 오래 열린 구매 확인창의 거래 번호 재사용도 차단한다.
- 아이템은 코인 상점에서 반복 구매한다. 구매만으로 활성화되지 않는다. 꾸미기는 기존 레벨 해금·가격(6/12)을 코인으로 유지하고 영구 보유·장착하며 생산 효과는 없다.
- 중요한 구매/사용/교환은 가격 또는 수량, 현재/변경 후 잔액·효과/보유 상태를 확인한다. 취소는 변경하지 않는다.
- 최종 교환은 Lv.10 + 코인 10(추정) 조건이다. 기기에 완주 기록만 한 번 남기며, UI와 확인창 모두 **모의 보상 수령·실제 지급 없음**을 명시한다. 현금·상품·포인트, 계좌, 개인정보, 외부 지급 API가 없다.
- 잔액·거래·재고·수령 상태를 동일 스냅샷에 저장한다. 저장 중 중복 명령을 차단하고 실패 시 해당 변경 전체를 되돌린다.

## 시간과 저장 v4

- 기존 SQLite DB 파일·`snapshots` 테이블·SQL schema 1을 유지한다. JSON body의 `formatVersion`만 4로 올려 v1/v2/v3를 읽는다. 경제 밸런스 버전은 2다.
- 구버전 별사탕 잔액은 `migration:v4` 거래로 코인에 1:1 이전한다. 기존 `stars` 필드는 호환용 보관 값이며 소비하거나 추가 지급하지 않는다. v4 재실행에서는 다시 이전하지 않는다.
- 레벨·스킬·재화·외형·설정·레벨 보상 기록을 보존한다. v1/v2 `rewardedLevels` 이전도 유지하며 이미 수령한 레벨 코인을 다시 지급하지 않는다. 구버전에 없던 일일 진행은 0으로 시작한다.
- 기존 1/1000 생산 나머지는 새로운 분모 2,000,000으로 손실 없이 변환한다. 밀리초×permille×미접속 1/2를 정수 분자/분모로 계산하고 나머지를 저장한다. 클릭도 permille 나머지를 저장한다.
- 자동 생산 정산은 아이템 시작/만료 및 자정을 경계로 나눈다. 큰 tick과 작은 tick의 결과가 같고, 미접속 중 만료 전 구간만 배율을 적용한다. 기존 50%, 최대 8시간 미접속 정책을 유지한다.
- TimeService UTC와 단조 시계를 사용하며 관찰 UTC 최고값을 보존한다. 시계 역행으로 만료 효과가 부활하거나 이전 날짜가 재개되지 않는다. 접속 중 UTC 순방향 점프에는 경과 단조 시간만 생산하되 만료/날짜는 진행한다. 서버 시간 검증은 아니다.
- 평소 저장은 10초 주기, 중요한 명령은 즉시 저장한다. 일반 탭/렌더 프레임마다 저장하지 않는다. 활성 시간과 남은 시간은 저장된 기준 시각 및 종료 시각으로 재계산한다.
- 알 수 없는 설정 버전은 조용히 초기화하지 않고 오류 처리한다. 효과/목표 값은 별도 설정에서 바꿀 수 있지만, 배포 후 ID·버전·일일 목표 변경에는 새 마이그레이션 또는 시즌 정책이 필요하다. v4에서 이전 앱으로 내려가는 역방향 이전은 제공하지 않는다.

## 잔여 위험

- 가격·아이템 효과·일일 밸런스·교환 조건은 추정이며 시즌별 실제 원작 규칙을 검증한 것이 아니다.
- 코인 원장을 전부 보관한다. UI는 최근 30건만 보여 주지만 매우 장기간에는 스냅샷 크기/검증 비용이 증가하므로 서버 원장이나 중복 방지 ID를 유지하는 압축 설계가 필요하다.
- 로컬 시간/저장 파일 위변조를 완전히 막지 못한다. 네이티브 앱 생명주기·I/O 지연 경합·장시간 FPS/메모리는 실기기 검증이 필요하다.
- 저장 복원 자동 테스트는 SQLite와 같은 JSON body 계약을 사용하는 repository/controller 재생성 검사다. 실제 Android 네이티브 SQLite·OS 프로세스 종료/재시작 테스트와는 다르다.
- 일반 탭은 마지막 정기 저장 이후 일부 유실될 수 있다. 실제 초대/랭킹/계정·결제·현금 지급은 연결하지 않았다.
