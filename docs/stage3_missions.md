# 레벨 1~10 복합 미션

## 조건과 근거

레벨 N 조건은 **N에 도달하기 위한 조건**이다. 시작 레벨은 기존 저장과 동일하게 1이며, 현재 Lv.4에서 Lv.5 미션을 수행한다. 모든 조건을 달성해도 자동으로 올라가지 않고 버튼으로 레벨업과 보상을 한 번에 확정한다.

2026-09-29 확인한 공개 후기:

- [세종라이프 로그, 2025-12-10](https://dailysejong.tistory.com/entry/당근마켓-붕어빵게임-공략-총정리레벨-10-달성): 후반 생산·신규 초대 조건, 미션 시작 후 초대된 신규 플레이어가 레벨 1을 달성해야 인정되는 흐름.
- [cITy & ETC, 2025-12-05](https://citynetc.tistory.com/290): 1→2 생산 10개, 2→3 초당 1개, 3→4 황금버터 1회, 4→5 초당 5,000개 및 초대 1명 등의 플레이 기록.

공식 명세가 아닌 공개 후기이며 시즌 차이가 있을 수 있다. 첫 번째 후기로 신규 플레이어 조건을 구체화하고 두 번째 후기의 초반 조건을 함께 반영했다. 스크린샷·상표·캐릭터를 복사하거나 비공개 API를 호출하지 않았다.

| 도달 레벨 | 활성 조건 (전부 충족) | 근거 |
| --- | --- | --- |
| 1 | 초기 상태, 보상 수령 없음 | 기존 시제품 유지 |
| 2 | 튜토리얼 안내 확인 + 누적 생산 10개 | 안내 확인은 estimated, 10개는 공개 후기 |
| 3 | 초당 생산 1개 | 공개 후기 |
| 4 | 황금버터 사용 1회 | 공개 후기, 현재는 모의 사용 성공 입력 |
| 5 | 초당 생산 5,000개 + 신규 초대 1명 | 공개 후기 |
| 6 | 초당 생산 1,500만 | 공개 후기 |
| 7 | 초당 생산 5억 + 신규 초대 1명 | 공개 후기 |
| 8 | 초당 생산 200억 | 공개 후기 |
| 9 | 초당 생산 5,000억 + 신규 초대 1명 | 공개 후기 |
| 10 | 초당 생산 20조 + 신규 초대 3명 | 공개 후기 |

레벨별 보상은 기존 재화인 별사탕 3개를 유지한 **estimated** 설정이다. 실제 원작 보상 수량이라는 의미가 아니다. 이전 경제 단계의 추정 누적 생산 목표는 미션의 추가 조건으로 남기지 않았다. 가격·스킬 효과는 변경하지 않았다.

## 데이터와 규칙

- `mission_config.dart`의 목록으로 미션 종류·목표·보상·근거·출처를 정의한다. 금액과 목표는 십진 문자열에서 BigInt로 읽는다. 화면 진행 막대만 0~1의 double로 변환한다.
- `currentMissionSeason`은 신규/이전 데이터가 시작하는 설정이다. 저장에 시즌 ID를 고정한다. 새 시즌은 기존 정의를 보존하고 `missionSeasons`에 다른 ID로 추가해야 한다. 기존 ID의 조건을 수정하면 그 시즌의 활성 미션도 바뀌므로 배포 후에는 새 ID를 권장한다. 알 수 없는 시즌은 초기화하지 않고 오류 처리한다.
- `missions.dart`가 현재 활성 미션의 진행률·완료·수령 가능 여부를 평가한다. 과거/미래 미션의 진행은 0·미활성으로 반환한다. 미래 화면은 목표만 미리 보여 준다.
- 생산 목표는 현재 생산율/누적량의 문턱이다. 미션 시작 후 새로 생산해야 하는 목표가 아니다. 초대와 황금버터 사용은 현재 활성 미션에만 기록하며 다음 단계로 넘기지 않는다.
- 보상은 레벨 번호를 중복 방지 키로 사용한다. 시즌이 달라져도 같은 도달 레벨 보상을 재지급하지 않는다. UI에서 눌렀던 도달 레벨을 명령에 전달하므로 오래된 버튼 콜백으로 다음 레벨을 잘못 수령할 수 없다.
- 수령 기록·레벨·별사탕·다음 미션 활성화를 한 스냅샷으로 저장한다. 저장 중 중복 명령을 차단하고 실패하면 이전 상태로 복구한다. 생산이나 앱 복귀만으로 레벨 보상을 수령하지 않는다.

## 초대 문맥과 모의 기능

활성 문맥은 시즌 ID, 목표 레벨, 활성 세대 번호, TimeService UTC 활성 시각으로 구성한다. 모의 성공 이벤트는 플레이어 ID, 초대 당시 활성 토큰, 초대 시각, 완료 시각, 신규 여부, 레벨 1 달성 여부를 갖는다.

다음 조건을 모두 만족해야 현재 초대 미션에 집계한다:

- 현재 단계에 신규 초대 미션이 활성화되어 있음.
- 토큰이 현재 문맥과 일치하고 초대 시각이 활성화 시각 이후임. 같은 밀리초라도 토큰이 이전 단계이면 제외.
- 신규 플레이어이고 레벨 1을 달성했음.
- 완료 시각이 초대 이전이나 현재 시각 이후가 아님.
- 동일 플레이어를 이전에 처리하지 않았음.

집계되지 않는 이전 초대/기존 플레이어 성공도 처리 ID를 저장하여 다음 단계에서 신규 초대로 재사용하지 못하게 한다. 미완료·미래·잘못된 이벤트는 저장하지 않는다. 저장 실패한 이벤트는 ID도 되돌아가므로 같은 성공을 안전하게 재시도할 수 있다. 시제품의 처리 ID 보관 상한은 설정값 1,000건이며 실제 게임 규칙이 아니다.

일반 친구 초대 화면과 레벨 미션 화면에 **모의 데이터/모의 기능**을 명시한다. ‘신규 1명 초대 성공 생성’은 실제 연락처·메시지·계정·네트워크를 사용하지 않는다. 현재 초대 미션이 없거나 완료되면 생성 버튼을 비활성화한다.

황금버터 미션은 아이템 시스템 이전 단계이므로 **사용 성공 모의 입력**만 제공한다. 실제 아이템 소비·생산 증폭·아이템 지급은 없다. 요정·기존 플레이어 초대 보상도 이번 작업에 포함하지 않았다. 실제 초대 연결 시에는 클라이언트가 보낸 시각/신규 여부를 신뢰하지 말고 서버 검증 결과와 영속 중복 방지 키로 대체해야 한다.

## 저장 v3 마이그레이션

SQLite `snapshots` 테이블, current/backup 트랜잭션과 BigInt 문자열 저장은 그대로 유지한다. 테이블 구조 변경 없이 JSON 본문 `formatVersion`을 3으로 올렸다. 경제 밸런스 버전은 2를 유지한다.

- v1/v2의 `rewardedLevels`를 `levelRewards`로 옮긴다. 마이그레이션만으로 재화를 지급하지 않는다. 기존 레벨·재화·스킬·외형·설정·생산 나머지를 보존한다.
- 구버전에는 보상 수령 시각/당시 금액이 없으므로 `source: legacy`, 원본 버전 ID, 금액·시각 null로 기록한다. UI에도 금액·시각 미상으로 표시한다.
- 구버전에는 초대 기록이 없으므로 활성 초대 진행은 0이다. 현재 레벨의 다음 목표만 활성화한다. 시작 시각은 저장된 과거 시각으로 추정하지 않고, 최초 실행에서 주입된 TimeService로 생성·저장한다.
- 새 수령 기록은 레벨·시즌·BigInt 금액·UTC 시각을 저장한다. 활성 문맥과 처리/집계 플레이어 ID도 복원한다. 앱 재시작은 활성 시각이나 초대 수를 초기화하지 않는다.
- 이미 높은 레벨인 사용자를 새 조건 때문에 강등하지 않는다. 이전 기록에 이미 지급된 다음 레벨 보상이 있다면 조건을 달성해 레벨은 올라가도 보상은 다시 지급하지 않는다.
- v3를 구버전 앱에서 읽는 역방향 마이그레이션은 제공하지 않는다.

## 테스트와 변경 파일

추가된 단위 테스트는 후기 조건/estimated 메타데이터, 각 후반 레벨 생산 목표 직전과 정확한 경계, 복수 조건 AND, 명시적 수령, 미리보기 비집계, 초대 시각·토큰·신규·중복·미완료·미래 결과 제외, 저장 실패 롤백/재시도, 중복 수령, 최대 레벨, 부분 진행 및 수령 후 10^100 별사탕 복원, v1/v2 보상 기록 이전을 검사한다.

UI 테스트는 360×800, 390×844, 412×915와 글자 1/1.5/2배에서 모의 초대 3명을 생성하고 레벨 10 보상을 받는 전 과정을 수행한다. 미리보기·황금버터 모의 입력·저장 실패 재시도·초대 비활성 상태도 확인한다.

기존 경제 시뮬레이션의 자동 레벨업 기대를 새 명시적 수령 동작으로 수정했다. 기존 성장 시간 상한과 재화 정확성 검증은 유지하고, 초대는 활성화 후에만 생성하도록 했다. 모의 초대 총 6명, 수령 기록 9개도 검증한다. 검증 정책은 매초 2회 클릭·효율 구매·모의 입력·즉시 수령이다. 이 조건에서 첫 구매 8초, 자동 생산 37초, 레벨 4는 37초, 레벨 5는 703초, 레벨 10은 4,183초였다. 실제 사람의 플레이 시간이나 초대에 걸리는 시간을 예측한 수치가 아니다.
