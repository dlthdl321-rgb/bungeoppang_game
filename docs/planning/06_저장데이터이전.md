# 저장 데이터 이전 — 숙련·영업·재고

2026-10-14 / 설계 제안. 현재코드는JSON v12·SQL1/current/backup이며 차기JSON버전은미정이다. 새기능의논리데이터를정리한것으로 실제파일/클래스/필드명확정이나사용자저장이전실행이아니다.

## 1. 기존자산보존

buns/lifetime·스킬수·레벨/보상·코인원장·별/환생·외형/착용·일일/주간/업적·premium.gold/grant/skillUnlocks를그대로보존한다. 내부상품gold_*·서버지갑·구매토큰을명칭변경때문에재생성하지않는다. 기존buns는붕어빵력이고제품재고로복제하지않는다. 외형보유/튜토리얼/누적생산을숙련/새도감완성으로바꾸지않는다.

실물수량은BigInt/10진문자열, 영업일순번·나이·수량은음수불가. 재고를맛별합계만저장하지않는다.

## 3. 불변식과새명세

보유AND숙련완료인맛만6구후보. 숙련완료는요구연습량과모든설정조건을충족해야하며도감완성/해금과일관된다. 개별발견5개만으로숙련을추론하지않는다. **숙련미완료레시피의즉석제작/판매가가능**하므로과거made밖양수수량거부·made밖모든결과금지는적용하지않는다. 제품출처와연습맥락을검증한다.

익힘은맛별5ID이며이름/경계는미정. 과거7단계초안값을신규5단계로자동대응시키는이전규칙은없다. 추후실제이전데이터가생기면명시변환표를정한다. 알수없는ID/중복ID/음수수량/미지원버전/숙련-해금불일치는조용히삭제/지급하지않고기존복구로연결한다.

## 4. 영업·신선도·오프라인

영업상태는앱종료에도저장한다. 날짜키정책은미정이므로KST자정/오전5시를저장포맷전제로삼지않는다. 같은영업날짜키는한번만인정하고새실제영업일만순번을증가시킨다. 묶음나이=인정순번차,0일제작·5영업일경과소멸. 미접속현실일수는차감하지않는다. 영업일증가/소멸/날짜키는하나의저장단위다.

영업중부재시간의붕어빵력은기존8시간/50%로만정산하고제품재고는지급하지않는다. 기존lastSettledUtc/savedAutoRate·observedUtc·잔여분과새영업상태의연결을정의해야한다. 구형앱에서떠나신형앱으로돌아오는첫구간은전환정책미정이며영업상태를소급생성해지급하거나기존권리를조용히없애지않는다.

## 5. 원자이전·복구

구형엄격파서→메모리변환→기존자산비교/왕복검증→현재/백업SQL트랜잭션→새current재읽기검증순서를제안한다. 저장순번·주기save와새명령은직렬화한다. 이전중실패는원본을보존하고복구화면으로연결한다. 백업은이후정기저장에교체되므로장기보관이아니며보관정책은미정.

연습결과/숙련/도감/해금,수확/묶음/회차,판매/재고차감/주문/확정대금,영업일/소멸,오프라인생산/정산cursor를각각원자처리한다. 실패시이전상태와세션pending을함께복원하고같은ID/결과로재시도한다. 복구는서버지갑을임의롤백하지않는다. 재설치/환생의신규진행보존은미정이다.

## 복합 구매·50레벨·기능 게이트 이전

기존레벨/보상·소유·붕어빵력·코인·gold/구매토큰을보존하고새시즌의최대레벨50·기능별해금·두비용가격버전·구매의도/서버영수증/로컬최종화·판매만족도/황금보상ID/지급대기를추가설계한다. 기존가격/보상/장부를새가격으로재작성하거나소유를재구매시키지않는다.

기존사용자의기능접근/친구관계·환생후레벨저하·신규성장기준값은미정이며조용히삭제/재잠금하지않는다. 별5개만점만확정이고최저별/세부단위는정책확정후검증한다. 미정확률/보상량을0이나확정지급으로저장하지않는다.

서버지갑과SQLite를단일원자저장으로표현하지않고지속구매의도/영수증으로일관성을복구한다. 서버성공뒤로컬실패·백업복구·판매별재추첨/재지급·기존appliedGrants동기화를검증한다. 구체처리상태와오프라인정책은 [경제계약](10_복합경제와50레벨해금.md)에서결정한다. 초기황금보너스·무료구매·도감완성선지급은생성하지않는다.

## 광고 일일 한도·지급 이전

광고일일키·보상완료/예약기록·시도/검증ID·serverGrant·지급대기를새계약으로관리한다. 기존저장에없는광고기록으로황금을생성하지않으며서버일일원장/지갑이권위다. 재설치/기기변경/로그인전후/백업복구로한도가초기화되거나동일보상을재지급하지않게정책을정한다. 초기광고일일기록의기본값·한도범위·비로그인승계·자정귀속은미정이다. 영업일/환생과광고카운터를혼용하지않는다.
