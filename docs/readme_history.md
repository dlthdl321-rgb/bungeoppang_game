## 자체 게임 콘텐츠 (8단계)

- **레벨 미션**: 배포 시즌은 `offline-v1`입니다. 친구 초대 조건(Lv.5·7·9·10)을 기본 외 꾸미기 1개 보유, 아이템 누적 사용 5회, 성운 공방(auto_11) 1단계 보유, 업적 12개 달성으로 바꿨습니다. 생산·초당 목표와 보상은 그대로입니다. v7 이전 저장은 새 시즌으로 옮깁니다. 진행 중인 단계의 초대 조건을 이미 채운 저장은 그 대체 조건을 완료로 인정합니다(`waivedGoals`).
- **게임 공유**: 배포 빌드는 OS 공유 창으로 소개 문구와 스토어 링크만 보내며 보상은 없습니다. 초대 시뮬레이터·추천 코드·개발자 도구는 디버그 빌드에서만 공유 화면을 통해 열립니다(`GameController.developerTools`, 기본값 `!kReleaseMode`). 초대 코드·모델은 서버 연결 때 다시 쓰기 위해 남겨 두었습니다.
- **내 기록**: 최고 초당 생산(아이템 제외), 누적 생산·굽기, 플레이 일수, 최고 콤보, 레벨 도달 시각, 오늘과 지난 최고 비교·신기록 표시. 기록 자체는 이 기기 것이며, 다른 플레이어와의 순위는 메뉴 → 온라인 랭킹에서 봅니다. 콤보는 1초 이내 직접 탭이 이어질 때만 쌓이며(길게 누르기 제외) 생산 효과는 없습니다.
- **주간 도전**: 매주 월요일 00:00(KST)에 시작해 7일 뒤 자동으로 다음 주가 시작됩니다. 목표 4개는 각각 한 번 수령하고, 받지 않은 보상은 주가 바뀌면 사라집니다. 계절 테마는 제목·문구만 바꿉니다. 기기 시계를 앞으로 돌리는 것은 서버 없이 막을 수 없습니다(시계를 되돌려도 지난 주는 다시 열리지 않습니다).
- **업적·도감**: 업적 20개, 보상은 코인 또는 칭호 5종입니다. 칭호 하나를 홈과 내 기록에 표시합니다. 도감은 꾸미기 보유와 칭호 수집을 보여 줍니다. 이전 '완주 기록' 교환 기록은 Lv.10 업적(칭호 '골목 명장')으로 이전하며, 그때 쓴 코인은 돌려주지 않습니다.
- 저장은 JSON v7입니다. 탭·콤보·기록 갱신은 메모리에만 두고 10초 주기 저장과 중요 명령 저장에 포함합니다.

## 온라인 랭킹 (16단계, 카카오 로그인)

9단계의 구글 리더보드를 16단계에서 게임 자체 랭킹으로 바꿨습니다. 자세한 내용은 [16단계 기록](stage16_kakao_login_ranking.md)을 보세요.

- **로그인**: 카카오톡이 있으면 카카오톡으로, 없거나 실패하면 카카오계정 화면으로 로그인합니다. 앱은 카카오 접속 토큰을 서버 함수 `authKakao`로 보내고, 서버가 카카오에 확인한 뒤 돌려준 Firebase 커스텀 토큰으로 로그인합니다. Firebase 세션이 남아 있으면 앱을 다시 켜도 로그인 상태입니다. 로그인은 사용자가 버튼을 누르거나 온라인 기능을 쓸 때만 열리고, 배경 동기화는 로그인 화면을 열지 않습니다.
- **랭킹**: 최고 초당 생산(아이템 제외), 누적 생산, 최고 콤보 3개. 메뉴 → 온라인 랭킹에서 상위 100명과 내 순위를 봅니다. 서버(`rankingSubmit`)는 최고 기록만 남기고, 1분 안에 다시 보내거나 비정상적으로 큰 증가는 거절합니다(기준: `lib/ranking_config.dart`, 서버와 같은 값인지 테스트로 확인).
- 점수는 탭마다 보내지 않습니다. 레벨업, 앱을 나갈 때, 순위 열기, 플레이 중 최대 5분마다 개선된 경우에만 보냅니다. 저장 파일과 무관합니다. 64비트 상한을 넘는 누적 생산은 상한으로 보내고 화면에 알립니다.
- **키가 없으면 온라인 기능이 꺼집니다.** `--dart-define=KAKAO_NATIVE_APP_KEY=...`(와 Firebase 설정)이 없으면 랭킹·친구는 "준비 중"으로 표시되고 게임은 오프라인으로 그대로 동작합니다. 키는 저장소에 넣지 않습니다. Android 매니페스트의 카카오 리다이렉트 scheme(`kakao<키>`)도 Gradle이 같은 dart-define 값으로 채웁니다.

```
flutter run --dart-define=KAKAO_NATIVE_APP_KEY=<네이티브 앱 키> --dart-define=FIREBASE_API_KEY=... (stage15 문서 참고)
```

점수는 기기에서 계산되므로 서버는 형식, 빈도, 증가 폭만 확인합니다. 조작을 줄일 뿐 완전히 막지는 못합니다.

## 친구 초대 시제품 (5단계 · 현재 디버그 빌드 전용)

> 8단계부터 아래 기능은 디버그 빌드에서만 열립니다. 배포 빌드는 위의 게임 공유를 씁니다.

홈 오른쪽 친구 초대 또는 레벨 미션에서 진입합니다. ‘추천 코드 · 초대 링크 만들기’가 이 기기의 가상 플레이어 ID와 추천 코드를 최초 생성·저장합니다. 이후 새 링크를 만들어도 코드는 같고 앱 재실행에도 보존됩니다. 서버 계정이나 전역 중복 검사에 의해 발급된 코드는 아닙니다. 모의 구현은 128비트 난수 ID를 사용합니다.

- 공유 문구에는 모의 기능·실제 서비스 연결 없음·실제 지급 없음을 표시합니다. `example.invalid`는 실제 수신 서버로 연결하지 않는 모의 주소입니다. 링크를 눌러 상대 앱을 자동 설치하거나 딥링크로 실제 계정을 등록하는 기능은 없습니다.
- 문구·링크 복사와 시스템 공유를 제공합니다. 시스템 공유창에서 사용자가 대상 앱·상대를 직접 선택합니다. 공유창 반환/취소/오류는 참여 성공 증거가 아니며 보상이나 방문을 만들지 않습니다. iPad 공유 위치도 전달합니다. 구현은 [share_plus 12.0.2 공식 문서](https://pub.dev/packages/share_plus/versions/12.0.2)를 따릅니다.
- 개발자 도구는 가상 상대 ID로 링크 클릭, 신규 사용자 판정, 레벨 1 달성, 기존 사용자 참여, 실패, 중복 판정을 생성합니다. 단계 순서와 같은 방문/사용자/링크인지 검사합니다. 동일 eventId 재전송과 활성 미션용 신규 성공 일괄 생성도 제공합니다. 실제 연락처나 개인정보는 사용하지 않습니다.
- 신규는 클릭→신규 판정→레벨 1 달성이 필요하며 전체 기간 한 번 성공합니다. 기존 참여는 클릭→기존 참여로 보상하지만 신규 초대 미션에는 포함하지 않습니다.
- 추정 보상은 **신규 성공: 요정 1개**, **기존 참여: 황금버터 1개**입니다. 받는 대상은 초대한 이 기기이며 상대 기기로의 지급은 없습니다. 코인 보상 기본값은 0이고 `invite_config.dart`의 BigInt 십진 설정으로 교체할 수 있습니다. 정확한 원작 지급 규칙을 확인했다는 의미가 아닙니다.
- 같은 상대는 신규/기존 구분을 합쳐 한국 시각 하루 한 번 보상합니다. 코인 0이어도 `invite:출처:YYYY-MM-DD:상대ID` 거래를 기록하여 아이템 지급을 보호합니다. 기존 사용자는 다음 날 새 방문으로 다시 참여할 수 있습니다.
- 자정에는 ‘오늘 보상’ 집계와 일일 자격만 새 날짜로 바뀝니다. eventId·전체 기간 신규 성공·과거 보상 거래는 지우지 않습니다. 지연 도착 이벤트는 수신일이 아닌 발생일에 귀속됩니다. TimeService의 역행 방지 시각으로 과거 날짜를 다시 열지 않습니다.
- 레벨 미션은 링크 생성 시 고정한 활성 토큰, 링크 생성 시각, 상대 클릭 시각을 모두 검사합니다. 활성화 이전 링크/방문은 나중에 레벨 1을 달성해도 현재 미션에 포함하지 않습니다. 같은 시각이라도 다른 활성 세대는 제외합니다. 보상 성공과 레벨 미션 자격은 별도로 기록합니다.

### 저장·서버 교체 계약

SQLite 테이블과 SQL 버전 1은 유지하며 JSON 본문 버전은 **7**입니다(8단계). v1~v6 마이그레이션에서 기존 재화·미션·원장·외형·초대 기록을 보존하며, v7에서 내 기록·주간 도전·업적을 추가하고 v6의 모의 이벤트 상태는 버립니다(받은 보상은 원장에 남음). 이전 `seenInvitePlayers`는 `legacyPlayers`로도 보관하여 신규로 재사용하거나 소급 보상하지 않습니다. 프로필은 첫 초대 작업에서 생성하며 기존 저장을 읽는 것만으로 신규 보상을 주지 않습니다.

`InvitationRepository`는 프로필 등록, 활성 문맥을 포함한 링크 생성, 처리 완료 eventId 집합을 받는 이벤트 조회를 제공합니다. `GameController(..., invitationRepository: ...)` 주입 지점을 교체하면 같은 UI·단계 판정·저장 명령을 사용합니다. `InvitationSimulator`는 별도 개발자 기능 포트이며 운영 저장소는 구현하지 않아야 합니다. 운영 출처에서는 모의 메서드가 차단됩니다.

향후 서버 어댑터는 인증된 상대 ID·신규 여부·레벨 달성·신뢰 시각을 검증하고, 안정적인 eventId·순서 및 실패 시 재전송을 제공해야 합니다. 저장에 성공한 eventId만 다음 조회에서 전달합니다. 선행 이벤트가 없는 역순 결과는 수령 처리하지 않아 재전송할 수 있습니다. 모의/서버 프로필·이벤트 출처를 섞지 않으며, 기존 모의 계정을 실제 계정으로 옮기는 정책은 서버 도입 때 별도 마이그레이션이 필요합니다.

방문 상태·이벤트 ID·아이템 지급·코인 거래·레벨 진행은 같은 게임 스냅샷에서 확정합니다. 저장 실패는 함께 롤백합니다. 조회 실패는 기존 진행을 지우지 않으며, 초기화/컨트롤러 종료 후 도착한 옛 응답은 새 세션에 적용하지 않습니다. 서버 조회는 화면의 새로고침 명령으로 실행하며 프레임마다 통신/저장하지 않습니다.

### 변경 파일 및 잔여 위험

신규 파일은 위 구조의 `invite_*`, `mock_invite_repository.dart`, `ui/invite_panel.dart`, `test/invite_system_test.dart`, `test/invite_widget_test.dart`입니다. 기존 `models.dart`, `game_controller.dart`, `ui/game_app.dart`, `ui/level_missions.dart`, `test/level_missions_widget_test.dart`, `tools/preview_home_test.dart`, 이 문서를 연결/이전/미리보기에 맞췄습니다. 시스템 공유 의존성은 `pubspec.yaml`/`pubspec.lock`에 추가했으며 Dart 최소 선언을 3.4로 올렸습니다. 기존 테스트의 목표나 골든 허용 오차를 약화하지 않습니다.

- 이 구현은 상대 기기를 검증하지 않습니다. 임의 가상 ID 생성·로컬 파일/시각 조작을 서버 없이 방지하지 못하며 운영 보상 시스템이 아닙니다.
- 모의 링크의 실제 수신·계정 연결은 미구현입니다. 추천 코드는 앱 데이터 삭제/초기화 시 바뀌며 기기 간 동기화되지 않습니다.
- 시제품 기록 상한은 링크/방문 각 1,000개, 이벤트 5,000개입니다. 최근 30개 방문을 표시하지만 원본 중복 방지 기록은 삭제하지 않습니다. 상한에 도달하면 추가 처리하지 않으며 운영에서는 서버 저장·페이지 조회·보존 정책이 필요합니다.
- 저장 자동 테스트는 JSON 계약과 repository/controller 재생성 검증입니다. 실제 OS 종료·Android 네이티브 SQLite·장시간 FPS/메모리 및 OS 공유창 수신 앱별 동작은 실기기 검증이 필요합니다. iOS 빌드/공유는 이 Windows 환경에서 검증하지 않습니다.

최종 검증 결과는 위 재현 감사 보고서에 기록합니다.

## 꾸미기·랭킹·이벤트 (6단계 · 랭킹과 고정 이벤트는 8단계에서 교체)

> 가상 랭킹(`ranking.dart`)과 고정 모의 시즌(`event_config.dart`)은 8단계에서 삭제했습니다. 이미 받은 이벤트 코인·아이템은 원장과 재고에 남아 있습니다. 아래 랭킹·이벤트 설명은 당시 기록입니다.

`cosmetic_config.dart`의 4개 카테고리를 각 슬롯에 장착합니다. 미리보기는 재화를 차감하거나 장착을 바꾸지 않습니다. 구매 시 가격과 전후 상태를 확인하며 이미 소유한 상품은 무료 재장착합니다. 붕어빵은 기존 저장 필드를 보존하고 배경·화로·장식은 `menu_state.dart`로 저장합니다. 모든 상품·가격·해금 조건은 추정이며 원본 상품 복제가 아닙니다.

`ranking.dart`의 다른 20명과 친구 관계는 모두 가상 데이터입니다. 내 점수만 실제 로컬 누적 생산을 반영합니다. 동점 공동 순위와 BigInt 정렬을 사용합니다. 실제 서버·친구 그래프·시즌 점수 공식은 없습니다.

`event_config.dart`에 고정 모의 시즌(2026-09-01 00:00Z ~ 2026-11-01 00:00Z), 참여자·선착순 수량·4단계 보상·선행 조건을 정의했습니다. 시작 포함/종료 미포함, 명시적 참여, 단계별 한 번 수령, 로컬 재고 하한 0, 거래 ID를 검증합니다. 개발자 도구의 수량 소진도 저장됩니다. 단계 보상과 코인 완주 교환은 서로 다른 모의 기능이며 실제 가치는 없습니다. 서버 없는 전역 선착순 보장을 주장하지 않습니다. 다음 시즌은 ID를 새로 만들고 이전 정의를 보존해야 기존 영수증을 읽을 수 있습니다.

주요 규칙은 `menu_rules.dart`, 명령은 `menu_controller.dart`, UI는 `ui/public_menus.dart`로 분리했습니다. `test/public_menus_test.dart`와 `test/public_menus_widget_test.dart`는 저장/마이그레이션/롤백/중복/시간 경계/초과 소진 및 세 화면 크기×세 글자 배율을 검사합니다.

## 개인정보와 Play 데이터 보안

게임 저장은 기기 안에서만 합니다. 온라인 기능에 로그인하면 카카오 회원번호와(동의 시) 카카오 닉네임, 아바타 꾸미기, 순위표 점수, 친구·초대·황금 붕어빵 기록이 개발자의 Firebase 서버(서울)에 저장됩니다. 카카오 친구 목록과 카카오톡 메시지는 쓰지 않습니다. [개인정보처리방침](privacy_policy.md)과 [Play Console 데이터 보안 양식 기준](play_data_safety.md)을 참고하세요. `test/no_tracking_sdk_test.dart`는 허용 목록 밖의 광고·결제·분석 SDK가 의존성에 들어오거나 Google Play 서비스 라이브러리가 추가되면 실패하고, release 병합 매니페스트가 있으면 인터넷·광고 ID·결제·Firebase·애널리틱스 항목도 검사합니다.

## 연출·사운드 (10단계)

- 탭: 누른 위치에서 +N이 떠오르고(최대 `maxFloatingGains`개), 붕어빵이 눌림·스쿼시·스트레치로 반응하며, 부스러기 파티클이 미리 만든 풀(`maxCrumbParticles`개, 할당 없이 재사용)에서 튑니다. 연타 콤보는 20·50에서 색이 바뀌고 탭마다 살짝 튑니다.
- 콤보 경제 보너스는 `feedback_config.dart`의 `comboBonus`로 켤 수 있으며 **기본값은 끔**입니다(켜면 기준 콤보 이상 직접 탭에만 배율 적용).
- 레벨업, 일일·주간 미션 보상, 업적, 아이템 사용 때 화면 위 축하 배너와 숫자 카운트업, 색종이(풀 `maxConfetti`개)가 나옵니다. 바텀시트 위에도 보이며 여러 개는 차례로 나옵니다. 구매는 효과음만 냅니다.
- 오프라인 보상은 꾸민 "다시 오셨네요!" 화면에서 비운 시간과 받은 양을 카운트업으로 보여 줍니다. 이 화면은 실제로 24시간 이상 비웠다가 돌아왔을 때만 뜹니다(앱을 새로 켤 때와 백그라운드에서 돌아올 때 모두, `feedback_config.dart`의 `offlineWelcomeAfter`). 그보다 짧으면 보상만 조용히 들어옵니다.
- 모션 줄이기(앱 설정 또는 시스템)가 켜져 있으면 파티클·스쿼시·색종이·떠오르는 숫자를 끄고, 숫자는 바로 최종값을 보여 줍니다.
- 효과음(탭·구매·보상·레벨업)과 잔잔한 BGM. 설정에서 효과음·배경 음악을 켜고 끄며 볼륨(0~100%)을 바꿉니다. 슬라이더는 손을 뗄 때 한 번만 저장합니다. 앱이 백그라운드로 가면 BGM을 멈추고 돌아오면 다시 재생합니다. 다른 앱 음악을 끊지 않도록 오디오 포커스를 섞기(mixWithOthers)로 둡니다.
- 저장 형식 v8: 설정에 `soundEffects`, `music`, `sfxVolume`, `musicVolume` 추가(v1~v7은 기본값 켬·70%·40%).

## 밸런스·엔드게임 (11단계)

- **밸런스 v3**: 후반 스킬은 가격이 단계마다 ×10이고 효과는 ×5.65입니다. 단계가 오를수록 효율이 떨어지므로 생산이 폭주하지 않습니다. 오프라인 시즌의 Lv.6~10 초당 목표도 조정했습니다. "일반 사용자" 시뮬레이션(하루 2~3회 접속, 6~12분, 초당 2~4회 탭, 오프라인 보상 포함; `test/economy_simulation_test.dart`)에서 Lv.5 1일차, Lv.10 **21~22일차**입니다. 테스트가 세 시드에서 목표 곡선을 단언합니다. 변경 전후 표는 [11단계 기록](stage11_balance_endgame.md)에 있습니다.
- **새 노점 열기(프레스티지)**: Lv.10 이후 붕어빵·스킬·레벨을 초기화하고 명성 별을 받습니다(총 별 = ⌊∛(전체 누적 생산 ÷ 1경)⌋). 별 1개당 생산 +5%가 영구 적용됩니다. 코인·아이템·꾸미기·업적·기록·누적 생산은 유지되고, 레벨업 코인은 다시 지급되지 않습니다. 수치는 `prestige_config.dart`, 저장 형식은 v9입니다.
- **꾸미기 11종 추가**(모두 코드로 그림): 고구마·녹차·딸기 붕어빵, 눈 오는 밤·벚꽃 골목·바닷가 야시장, 무쇠·황금 화로, 별 전구·풍경·눈사람.

## 사장님·붕어빵 꾸미기 분리 (12단계)

- **세 분류**: 꾸미기 화면 위의 [붕어빵][사장님][가게] 탭이 꾸미는 대상을 나눕니다. 붕어빵은 맛·무늬·토핑, 사장님은 피부톤·머리·옷·모자·도구, 가게는 배경·화로·장식입니다. 탭마다 미리보기가 다릅니다(붕어빵 확대 / 사장님 / 가게 전경).
- **사장님**: 홈의 카운터 뒤, 화로 오른쪽에 서 있습니다. 붕어빵을 탭하면 집게를 0.25초 들어 올리고, 모션 감소 설정이면 움직이지 않습니다. 피부톤 3가지는 무료이며 수집 대상이 아닙니다.
- **신규 17종**(145코인, Lv.2~9): 무늬 3·토핑 4, 머리 2·옷 3·모자 4·도구 1. 수집 대상은 35종이 되었습니다. 분류별 업적 '사장님 옷장 5벌'·'붕어빵 공방 5종'(각 3코인)을 추가했습니다.
- **그림**: `tools/draw_pixel_assets.py`가 도트로 그립니다. 무늬는 맛별 붕어빵 이미지(`fish/<맛>@<무늬>.png`)로 굽고, 토핑과 사장님 레이어(44×60)는 겹쳐 그립니다.
- **저장 v10**: v9 이하 저장은 새 슬롯에 기본값을 받고, 기존 맛·가게 꾸미기를 그대로 유지합니다. 규칙과 검증은 [12단계 기록](stage12_avatar_fish_customization.md)에 있습니다.
