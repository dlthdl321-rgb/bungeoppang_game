# 추가 생성 이미지(300장) 게임 적용 프롬프트

기준 폴더: [이미지/추가 생성 이미지/](../../이미지/추가%20생성%20이미지)
(README_KO.txt, manifest.json, generation_prompts.json, gallery.html 포함)

**원본 상태 (2026-10-07 확인)**
- 300장 모두 **RGB, 흰 단색 배경, 고해상도 원본**입니다. 배경 제거·축소·정렬이 안 된 RAW입니다.
- `avatar/*`는 슬롯 레이어가 아닙니다. 기본 사장님이 **그 항목 하나만 입은 전신 그림**입니다.
- `cook/*`는 조리 장면 전체입니다. `<boy|girl>_<1~6>.png`가 기본 6컷이고, `<캐릭터>_<컷>_<슬롯>_<id>.png`는 **항목 하나만 바꾼 같은 장면**입니다.
- `이미지/raw`, `이미지/preview`, `bungeoppang_raw_assets_*`, `붕어빵게임_개발에셋_*`는 지난 회차 자료라서 이번 작업 대상이 아닙니다.

문서 구성
- **A. Claude Code 작업 프롬프트**: 그대로 붙여 넣으면 됩니다.
- **B. 원본 → 게임 대응표**

## A. Claude Code 작업 프롬프트

```
"이미지/추가 생성 이미지" 폴더의 그림 300장을 게임에 모두 적용해줘.
기준 문서: docs/prompts/오늘의붕어빵_추가이미지적용프롬프트_261007_2012_01.md (B절 대응표)

[먼저 읽을 것]
- 이미지/추가 생성 이미지/README_KO.txt, manifest.json, generation_prompts.json (그림마다 의도가 적혀 있음)
- docs/prompts/오늘의붕어빵_이미지교체프롬프트_261006_1937_01.md (지난 회차 원칙)
- tools/pixelize.py, tools/concept_avatar.py, tools/palette.py
- lib/cosmetic_config.dart, lib/models.dart (formatVersion 12), lib/ui/pixel_sprites.dart
  (artPending, artStandIns, cookCharacters, iconNames), lib/ui/avatar_painter.dart,
  lib/ui/cook_cut.dart, lib/ui/night_home.dart, lib/ui/night_stall_painter.dart, pubspec.yaml

[규칙]
1. 원본 폴더는 수정하지 않는다. 처리 결과만 assets/images/ 아래에 쓴다.
   처리 스크립트는 tools/에 남겨서(예: tools/apply_extra_art.py) 다시 돌릴 수 있게 한다.
2. 기존 꾸미기 id와 파일 경로는 그대로 둔다. 같은 id 파일은 덮어쓰고, 새 파일은 B절의 경로를 쓴다.
3. 결과 이미지는 폴더별 현재 캔버스 크기와 맞춘다(아바타 280x520, 조리 506x506, 붕어빵·토핑 96x72,
   배경 335x762 등은 실제 파일을 열어 확인). 투명 배경 RGBA로 만들고 nearest-neighbour로만 확대한다.
4. 흰 배경은 테두리에서 시작하는 flood fill로만 지운다. 흰 티셔츠, 요리사 모자·옷, 슈가파우더, 눈사람처럼
   흰색이 많은 그림은 속까지 지워지지 않았는지 미리보기로 꼭 확인한다.
5. avatar/* 전신 그림은 그대로 레이어로 쓰지 않는다. 같은 캐릭터의 기본 그림(base)과 위치·크기를 맞춘 뒤
   달라진 픽셀만 남겨 슬롯 레이어(<slot>_<id>.png)를 만든다.
   머리·피부·표정처럼 기본 그림을 덮어써야 하는 항목은 차분 레이어로 기존 머리가 비쳐 보이면
   '기본 그림 교체(base 변형)' 방식으로 바꾸고, 어떤 방식을 골랐는지 보고한다.
6. 조리 컷도 같은 방식이다. 기본 컷과의 차분으로 항목 레이어를 만들어서 여러 항목을 동시에 입혀도 그려지게 한다.
   차분이 깨끗하지 않으면 '대표 항목 하나만 반영' 규칙(우선순위 제안)으로 대신하고, 그 사실을 보고한다.
7. 새 슬롯(표정 face)이나 새 항목이 생기면 formatVersion을 올리고 이전 세이브를 마이그레이션한다
   (새 슬롯은 기본값 장착, 기존 보유·장착은 유지). 마이그레이션 테스트도 추가한다.
8. 새 항목의 가격·해금 레벨은 기존 분포(코인 3~15, Lv.1~9)에 맞춰 제안하고, 업적 '꾸미기 전부 수집'
   목표 수가 어떻게 바뀌는지 보고한다. 경제 수치는 바꾸지 않는다.
9. 그림이 생긴 id는 PixelSprites.artPending과 artStandIns에서 뺀다. 새 폴더(deco, customer 등)는 pubspec.yaml에 추가한다.
10. tools/draw_pixel_assets.py는 --only 없이 실행하지 않는다. 스킬 그림·화면·코드는 건드리지 않는다.

[진행 순서: 단계마다 멈추고 보고]
0단계: 대응표 확정
  - manifest.json의 300장을 하나씩 B절 대응표에 넣어서 '교체 / 신규 / 이름만 다름 / 쓰지 않음'으로 분류한다.
    표에 없는 파일이나 애매한 이름이 있으면 목록으로 묻는다.
  - 처리 파라미터(크기, --colors, --tolerance)를 폴더별로 정하고, 샘플 한 장씩 미리보기를 보여준다.
1단계: 붕어빵·토핑·화로 (fish 3, topping 4, stove 3)
2단계: 배경 (bg 14): 낮 그림 교체, 신규 4종(dusk, forest, night, seaside), 밤 그림 4종(*_night)
  - 원본 배경에 붕어빵·틀·카운터가 그려져 있으면, 게임이 그 위에 따로 그리는 것과 겹치지 않는지 확인하고 처리안을 보고한다.
3단계: 장식 (deco 6) + 아이콘 (icons 17)
  - 이미 iconNames에 있는데 파일이 없던 아이콘을 채우고, 새 아이콘(back, bgm, sfx, vibration, volume, save, menu)은
    설정·메뉴·돌아가기 버튼에 연결한다. 지금 Material 아이콘이나 대체 그림을 쓰는 곳을 찾아 바꾼다.
4단계: 사장님 전신 (avatar boy 27, girl 25)
  - 슬롯 레이어 추출, 표정(face) 슬롯 신설, 남자 사장님의 빠진 레이어 채우기
5단계: 조리 컷 (cook 252)
  - cookCharacters에 'boy' 추가, 기본 6컷 교체, 항목별 레이어 추출, 장착 상태가 조리 컷에 반영되게 연결
6단계: 손님 모션 (customer 7)
  - 걷기(walk_1·2) → 서기(stand) → 주문(order) → 받기(receive) → 떠나기(leave_1·2) 흐름으로 거리 손님을 추가한다.
    레이어 순서는 배경 → 날씨 → 손님 → 매대. 모션 감소 설정이면 걷기 애니메이션을 생략한다.
7단계: 확인
  - 캐릭터 2명 × 모든 꾸미기 항목, 배경 14종 낮/밤, 장식 6종을 미리보기 시트로 만들어 보여준다.
  - flutter test 통과(골든 이미지가 바뀌면 갱신하고 바뀐 목록 보고), 이전 세이브 불러오기 확인.
  - 최종 보고: 적용한 파일 수 / 쓰지 않은 파일과 이유 / 아직 그림이 없는 id 목록.
```
