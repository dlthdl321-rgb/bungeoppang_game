# Play 게임즈 → 카카오 로그인 전환 프롬프트

**현재 상태 (2026-10-07 확인)**
- 출시 전이라 실제 사용자가 없습니다. 계정 이전 기능 없이 **통째로 교체**합니다.
- 로그인: Play 게임즈 → `serverAuthCode` → Firebase `PlayGamesAuthProvider`
  ([lib/firebase_online_backend.dart](../../lib/firebase_online_backend.dart) `signIn()`)
- 서버: 모든 callable이 `signedIn(req)`에서 `sign_in_provider === "playgames.google.com"`만 허용합니다
  ([firebase/functions/src/index.ts](../../firebase/functions/src/index.ts)).
- 랭킹: Play 게임즈 리더보드 3개(`bestAutoRate`, `lifetime`, `bestCombo`)에 점수를 올리고, 순위 화면도 구글 기본 화면을 씁니다
  ([lib/online_ranking.dart](../../lib/online_ranking.dart), [PlayGamesBridge.kt](../../android/app/src/playGames/kotlin/com/todaybungeoppang/todays_bungeoppang/PlayGamesBridge.kt)).
- 결제(Google Play Billing)와 서버 지갑, 친구, 초대 기능은 Firebase uid 기준이라 로그인 방식과 관계없이 그대로 씁니다.

문서 구성
- **A. Claude Code 작업 프롬프트**: 그대로 붙여 넣으면 됩니다.
- **B. 직접 해야 하는 콘솔 작업**: 사람이 직접 하는 설정입니다.

## A. Claude Code 작업 프롬프트

```
Google Play 게임즈 로그인과 리더보드를 없애고, 카카오 로그인과 자체 온라인 랭킹으로 바꿔줘.
아직 출시 전이라 기존 사용자 이전이나 호환은 필요 없어.
기준 문서: docs/prompts/오늘의붕어빵_카카오로그인전환프롬프트_261007_2100_01.md

[먼저 읽을 것]
- lib/firebase_online_backend.dart, lib/online_backend.dart, lib/online_controller.dart
- lib/online_ranking.dart, lib/ranking_config.dart, lib/ranking_controller.dart, lib/main.dart
- lib/ui/progress_panels.dart (_OnlineRankingCard), lib/ui/gold_widgets.dart, lib/premium_controller.dart
- firebase/functions/src/index.ts (signedIn), friends.ts, store.ts, firebase/firestore.rules, firebase/functions/test/
- android/app/build.gradle.kts, android/app/src/main/AndroidManifest.xml, MainActivity.kt,
  android/app/src/playGames/, android/app/src/noPlayGames/, android/app/src/main/res/values/games-ids.xml
- test/stage9_ranking_test.dart, test/widget_test.dart, docs/stage9_play_games_ranking.md

[1. 카카오 로그인 (앱)]
- pubspec에 kakao_flutter_sdk_user를 추가한다.
- 네이티브 앱 키는 코드에 박지 않는다. --dart-define=KAKAO_NATIVE_APP_KEY=... 로 받는다.
  키가 비어 있으면 온라인 기능은 "준비 중"으로 숨기고, 게임은 오프라인으로 정상 동작해야 한다.
  지금 Play 게임즈 app_id가 비었을 때와 똑같이 동작하게 한다.
- main에서 KakaoSdk.init(nativeAppKey: ...)을 호출한다. AndroidManifest에는 AuthCodeHandlerActivity와
  kakao{키} scheme을 넣는다. scheme은 gradle에서 manifestPlaceholders로 같은 dart-define 값을 쓴다.
- 로그인 순서: 카카오톡이 설치돼 있으면 loginWithKakaoTalk, 실패하거나 미설치면 loginWithKakaoAccount
  → 액세스 토큰을 callable `authKakao`로 보냄 → 돌려받은 Firebase 커스텀 토큰으로 signInWithCustomToken.
  사용자가 직접 취소한 경우는 오류 메시지 없이 조용히 끝낸다.
- 앱을 다시 켜면 Firebase 세션이 살아 있는 동안 자동으로 로그인 상태를 유지한다.
- 로그아웃 버튼을 둔다(Firebase signOut + 카카오 logout). 계정 탈퇴는 이번 범위가 아니다.
- displayName은 카카오 닉네임(동의한 경우)으로 쓰고, 없으면 기존 기본 닉네임 규칙을 쓴다.

[2. 서버 (firebase/functions)]
- 새 callable `authKakao`:
  {accessToken}을 받아 https://kapi.kakao.com/v2/user/me 로 검증한다.
  /v1/user/access_token_info의 app_id가 우리 앱 ID(환경 변수 KAKAO_APP_ID)와 같은지도 확인해서
  다른 앱에서 발급된 토큰은 거절한다.
  uid는 "kakao:<회원번호>"로 정하고, createCustomToken(uid, {provider: "kakao"})를 돌려준다.
  닉네임이 있으면 Auth 사용자 displayName에 반영한다.
  카카오 API 호출 부분은 주입 가능하게 만들어서 테스트에서 가짜로 바꿀 수 있게 한다.
- signedIn(req): Play 게임즈 확인을 없애고, sign_in_provider가 "custom"이면서
  token.provider === "kakao"인 경우만 허용한다. 오류 문구도 카카오 기준으로 바꾼다.
- 결제 검증(walletRedeem)은 Google Play Developer API를 그대로 쓴다. 바꾸지 않는다.

[3. 자체 랭킹 (Play 게임즈 리더보드 대체)]
- callable `rankingSubmit` {bestAutoRate, lifetime, bestCombo}:
  Firestore rankings/{board}/entries/{uid}에 {score, name, look, updatedAt}을 저장한다.
  점수는 기존보다 높을 때만 올린다(최고 기록). 값 상한은 기존 rankingScoreMax를 그대로 쓴다.
  uid당 너무 잦은 호출은 거절한다(기존 rankingSubmitIntervalMs 기준).
  말이 안 되게 큰 점수 증가는 거절한다. 판단 기준은 ranking_config에 상수로 둔다.
- callable `rankingTop` {board}: 상위 100명과 내 순위·점수를 돌려준다.
  내 순위는 count() 집계 쿼리로 구하고, 필요한 인덱스는 firestore.indexes.json에 추가한다.
- firestore.rules: rankings는 클라이언트가 직접 읽지도 쓰지도 못한다. 접근은 functions로만 한다.
- functions 테스트를 추가한다: authKakao(정상 / 다른 앱 토큰 / 만료 토큰), signedIn,
  rankingSubmit(최고 기록만 반영 / 빈도 제한 / 비정상 점수), rankingTop.

[4. 앱 랭킹 화면]
- RankingService 인터페이스는 유지하되, Play 게임즈용 구현을 Firebase 구현으로 바꾼다.
  showLeaderboards()는 없애고 순위를 가져오는 메서드로 바꾼다.
- _OnlineRankingCard 대신 게임 안 랭킹 화면을 만든다. 탭 3개(초당 생산, 누적 생산, 콤보)에
  상위 100명 목록과 내 순위를 맨 아래에 고정해서 보여준다.
  기존 UI 컴포넌트와 픽셀 스타일을 그대로 쓰고, 아바타가 있으면 친구 목록과 같은 방식으로 표시한다.
- 큰 숫자는 기존 숫자 포맷 함수로 표시한다. 오프라인이나 미로그인 상태에서는 로그인 버튼과 안내만 보여준다.

[5. Play 게임즈 제거]
- play-services-games-v2 의존성, playGames/noPlayGames 소스셋 분기, PlayGamesBridge(두 버전 모두),
  games-ids.xml, MainActivity의 PlayGamesBridge 호출, MethodChannel 'todays_bungeoppang/play_games'를 삭제한다.
- 문구에서 "Play 게임즈"와 "Google Play 게임즈"를 "카카오 계정"으로 바꾼다.
  gold_widgets의 "이 계정(Google Play 게임즈)에 보관" 문구도 포함한다.
  단, "결제는 Google Play로 처리돼요" 같은 결제 문구는 그대로 둔다.
- README, docs/privacy_policy.md, docs/play_data_safety.md에서 수집 항목과 제3자 제공 내용을
  카카오(회원번호, 닉네임) 기준으로 고친다. docs/stage9_play_games_ranking.md는 맨 위에
  "카카오 전환으로 대체됨"이라고 적고 새 문서 docs/stage16_kakao_login_ranking.md를 만든다.
- grep -ri "playgames\|play games\|play 게임즈\|PlayGames" 결과가 0건이어야 한다(이 프롬프트 문서는 제외).

[6. 테스트와 확인]
- test/stage9_ranking_test.dart와 widget_test.dart를 새 구조에 맞게 고친다.
  로그인 성공, 취소, 실패, 키가 없을 때 숨김, 랭킹 표시를 FakeOnlineBackend로 테스트한다.
- flutter analyze, flutter test, functions 테스트(npm test)가 모두 통과해야 한다.
- 키 없이 flutter build apk --debug가 성공해야 한다.

[하지 말 것]
- 카카오 친구 API나 카톡 메시지 공유는 이번 범위가 아니다. 비즈 앱 검수가 필요하다.
- 키, 시크릿, 서비스 계정 파일은 커밋하지 않는다.
- 커밋은 내가 요청할 때만 한다.

마지막에 바뀐 파일 목록, 내가 콘솔에서 해야 할 일(B절), 테스트 결과를 한국어로 정리해줘.
```

## B. 직접 해야 하는 콘솔 작업

1. **카카오 개발자 콘솔** (developers.kakao.com)
   - 애플리케이션 추가 → **네이티브 앱 키**와 **앱 ID**를 확인합니다.
   - 플랫폼 → Android: 패키지명 `com.todaybungeoppang.todays_bungeoppang`, 키 해시 3개
     (디버그 키, 업로드 키, **Play Console 앱 서명 키**)를 등록합니다.
   - 카카오 로그인 → 활성화 ON, 동의항목 → 닉네임(선택 동의)을 설정합니다.
2. **Firebase / Google Cloud**
   - Functions 환경 변수에 `KAKAO_APP_ID`를 등록합니다.
   - 커스텀 토큰 발급 권한: Functions 실행 서비스 계정에 **서비스 계정 토큰 생성자**
     (`roles/iam.serviceAccountTokenCreator`) 역할을 줍니다. 이 권한이 없으면 `createCustomToken`이 실패합니다.
   - Authentication → Play 게임즈 제공업체는 사용 중지해도 됩니다.
3. **Play Console**
   - Play 게임즈 서비스 프로젝트(리더보드)는 더 이상 쓰지 않습니다. 결제(인앱 상품)는 그대로 둡니다.
   - 데이터 보안 양식을 카카오 기준으로 다시 제출합니다.
4. **빌드**
   - `flutter run --dart-define=KAKAO_NATIVE_APP_KEY=<네이티브 앱 키>`
