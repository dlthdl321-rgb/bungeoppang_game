# 손님 콘텐츠 구현과 현재 환경 후속

2026-10-16 / 코드·기획 수정과 정적 확인 기록. **앱 실행·Dart 타입/컴파일·Flutter/서버 테스트·빌드·실서비스·실기기는 미실행**이다. 아래 연결은 소스 경로를 뜻하며 동작 통과나 작업 완료를 뜻하지 않는다.

## 1. 사용자 추가 확정

- DEC-017: 입장 순간부터 줄 전체 개인 타이머가 흐른다. 별도 수락으로 무제한 대기하지 않는다.
- DEC-004/017: 잘못 고른 제품은 소비하지 않고 재선택한다. 교환1회·추가15초 유예를 도입하지 않는다.
- DEC-016/017: 도윤부터 네임드 하루 최대2명 소개, 8명은 최소4영업일에 걸쳐 소개. 첫 도윤은 팥 주문이며 슈크림은 실제 획득 후 사용한다.
- 무기명 손님도 추가 방문한다. 무기명은 매 방문 ID를 구분하고 영구 NPC 친밀도·취향 도감 인물로 등록하지 않는다. 일반 대금·판매 황금 심사는 기존 판매 계약을 동일 적용한다.
- 무기명/휴일 비율 각30%, 막례 자기 몫 추가1개 등 숫자는 공통 설정의 개발 임시값이다. 실제 빈도는 보장하지 않으며 큐/레벨 한도와 네임드 하루 방문 제한을 우회하지 않는다.

## 3. 실제 연결과 안전 경계

- main → 기존 WorkshopController → 고정 NPC 방문 → 주문/관찰 → 전량 판매·일반 대금/판매 황금 대기·친밀도를 같은 command/save로 저장한다. 실패하면 같은 방문·주문·재고·관계로 복원한다. 로컬 황금 지급은 없다.
- schema3 구매/미션/광고·보상 필드는 그대로 읽고 신규 관계는 빈 원장으로 시작한다. 구형 필드에 새 관계가 섞이거나 schema4 필수 관계/장면이 누락되면 거부한다. old customer_N은 이름을 추측해 새 NPC에 붙이지 않는다.
- 입장/주문·대기·초기 대기시간70% 지연·성공/시간 초과, 단계별 친밀/이웃 대사·기다리는 모습 확인과 관계/선택 장면·후일담을 연결했다. 대사 속 수량은 문장 그대로의 조건(예: 두 개/다섯 개)으로 검사하므로 주문 수치를 바꿔도 틀린 수량을 말하지 않는다. 시간대/날씨/구체 품질을 확인할 근거가 없는 일반 대사는 중립 문장으로 대체한다. 카탈로그에144문장이 있다는 사실과 모든 상황의 전용 연출 완료를 구분한다. 교환/추가유예는 사용자 미채택 정책이므로 활성화하지 않는다.
- 오 작가 스케치는 실제 기다림 확인 이력, 태오 사건은 실제 신규 맛 판매·사진을 잊은 반응 확인, 민재/은채는 저장된 방문 맥락을 사용한다. 실제 촬영·SNS·건강정보를 수집하지 않는다.
- 선택 확정·친밀도·완료·후일담은 한 저장이다. 배웅은0/보류, 선택 후 반응 넘기기는 보상 유지, 다시 보기는 재보상하지 않는다. 같은 날 실패한 추첨도 저장해 재실행/추가 손님으로 재추첨하지 않는다.
- 일반 대기 말풍선은 시간을 멈추지 않는다. 관계/선택/후일담/다시 보기 장면만 영업 시뮬레이션과 경제 정산을 멈추고 실제 KST·서버 일일키는 유지한다. 앱 이탈 중 활성 장면이면 경제를 소급 지급하지 않는다. 광고는 기존 고객/제작 정지·경제 별도 계약이다.
- 서버가 믿을 보호 증거 생성 파이프라인이나 AdMob 서명 검증을 구현했다고 주장하지 않는다. 신규 관계 로컬 원장은 서버 황금 지급의 신뢰 근거가 아니다.

## 4. 얼마나 더 남았는가

전체 원장40개 중 완료1·검토중30·차단2·미착수7. P6-006은 정적 통합 소스/검수 소스 작성으로 검토 중이며 실행 조건이 남아 완료가 아니다. 문서/코드 부분 진행률을 임의 퍼센트로 합산하지 않는다.

이번 손님 후속에서 처리한 묶음은8개이며, 다음 작업은3종류다.

1. **후속 기능 연동:** 기존 상태에 근거한 입장/주문/대기/지연/판매/이탈·친밀/이웃 대사는 소스에 연결했다. 동행·날씨/시간대·외형 변화/정확한 제품 모양처럼 아직 없는 기능은 참으로 가정하지 않고 비활성/중립 대사로 처리한다. 첨부가 후속으로 구분한 동행/행동/날씨 기능을 새로 만들고 연출을 검수하는 일은 남는다. 전체144문장 연출 완료로 보고하지 않는다.
2. **콘텐츠·운영 준비:** 표정24종·복장/특별 행동·실제 날씨/시간대 아트, 운영 광고/서버 보호 증거·계정/정책 검토는 별도다. 사용자 제한 범위인 코드/기획을 넘어 이미지·실서비스 작업을 실행하지 않았다.
3. **허용되지 않은 실행 검수:** Dart 타입/앱·Flutter/서버 테스트·SQLite 이전/실패주입·빌드·실제 광고/결제·실기기. 이번 테스트21개는 이 검수를 대신하지 않는다.

현재 손님 정책 질문3개는 모두 답변받아 반영했다. 같은 결정을 다시 묻지 않는다. 시간·추가 공수는 실측 전 미산정이다.
