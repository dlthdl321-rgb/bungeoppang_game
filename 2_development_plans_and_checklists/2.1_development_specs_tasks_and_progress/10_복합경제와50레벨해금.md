## 광고 타이머 승인·복구 검토 후속 — 2026-10-16

사용자 승인으로 광고 시청 중 손님 대기·큰 틀 제작·6구 익힘을 일시정지하고 같은 진행에서 재개하며 광고 시간을 해당 타이머에 소급 반영하지 않는다. 영업 상태·붕어빵력 정산·서버 광고 날짜/검증/예약 시각은 별도다. 일반 제작 중 손님 시간이나 모든 앱 이탈을 정지시키는 승인으로 확대하지 않는다. 강제 종료·겹친 정지 사유의 실제 복구는 [13번 검토](13_저장이전과구매복구위험검토.md)의 구현 전 게이트다. [14번 밸런스 초안](14_밸런스조정용미승인초안.md)은 작성만 승인됐으며 가격·횟수·확률·레벨 출시값은 미승인이다. SDK·보상량도 미정이며 앱/서버 실행 검수는 하지 않았다.

## 2026-10-16 온라인 구매·판매 심사·광고 일일 기준 확정

이번 사용자 답변에 따라 복합 상품/스킬은 온라인에서만 구매한다. 오프라인 일반 플레이는 유지하고 중단된 결제는 같은 거래 ID로 복구한다. 오프라인 판매의 황금은 판매 증거를 저장해 연결 후 서버 검증·1회 추첨하며 검증 불가 지급을 보장하지 않는다. 광고는 로그인 계정별 하루 최대2회, KST 자정, 서버가 시작을 승인한 날짜에 귀속한다. 자정 이후 완료/검증도 시작일에 포함하고 여러 기기가 한도를 공유한다. 기존 본문의 관련 추천/미정 표시는 이 세 범위에서만 해소한다. 가격·확률·보상량·SDK·광고 정지 중 앱 이탈 복구·구체 복구 구현은 별도 미정이다. [질문 답변 원문](2.1.1_game_rules_and_decisions/00_결정취합.md)과 [선행 설계](12_선행기획검토와복구설계.md)를 따른다.

## 최신 확정 반영 — 2026-10-16

10월 15일 [사용자 답변 기록](2.1.1_game_rules_and_decisions/00_결정취합.md)의 첫~세 번째 답변이 이전 미정/추천 문장보다 우선한다. 팥 미디엄 레시피만 기본 지급하고 구매 없이 핵심 진입한다. 다른 익힘은 직접 만들어 수집하며 해당 익힘의 선구매를 요구하지 않는다. 숙련은 맛별이고 **연습5종 수집 AND 인정 연습량 AND 손기술 통과량**을 모두 요구한다. 저장 확정된 실패 완주 연습은 연습량에 포함, 주문 제작은 수집만 인정한다. 초기 숙련/6구/도감완성을 선지급하지 않는다. 덜 익음은 특별 주문 판매 가능이며, 6구 수확/제품 보관은 여전히 다음 질문 대기다. 최종 단계 명칭·미디엄 대응·손기술 세부 기준·횟수·가격·확률·광고량은 새로 확정하지 않는다.

[선행 작업별 대조와 복구 설계](12_선행기획검토와복구설계.md)를 함께 읽는다. 아래 구형 설명에서 실패 인정·주문 반영·5종 관계를 통째로 미정이라고 표현한 부분은 이 확정 범위로 한정해 읽는다. 코드/데이터 이전·실행 검수는 하지 않았다.

## 1. 상점·스킬의 복합 가격 — DEC-021 확정

상점 상품과 스킬은 **붕어빵력 AND 황금붕어빵력**을 함께 요구한다. 한 재화를 골라 내거나 황금붕어빵력으로 붕어빵력 부족분을 대신 내는 방식이 아니다. 아이템/스킬마다 두 비용을 별도로 관리하며 금액은 미정이다.

| 가격 정보 | 관리 원칙 |
| --- | --- |
| 상품/스킬 ID·가격 버전 | 기존 식별자 보존, 결제 견적과 서버 가격표 연결 |
| 붕어빵력 비용 | 해당 항목의 소비 잔액. 누적 획득량을 차감하지 않음 |
| 황금붕어빵력 비용 | 해당 항목의 서버 지갑 비용. 기존 코인 가격×5 등으로 자동 환산하지 않음 |
| 개수/구매 회차 | 스킬 반복/묶음 구매의 두 재화 합계를 함께 산출. 증가율과 최대 구매 계산은 새 가격표에 맞춰 결정 |

구매 가능 = 상품/기능 해금 충족 **AND** 붕어빵력 잔액 충분 **AND** 황금붕어빵력 잔액 충분이다. 화면에는 두 가격·두 보유량·각각의 부족 사유와 최종 결제 견적을 표시한다. 부족한 경우 어느 쪽도 최종 차감하거나 소유/스킬 수를 올리지 않는다.

이 규칙은 재화를 소비하는 상점 상품·스킬 구매에 적용한다. **황금붕어빵력 충전 IAP는 실제 결제 경로**이며 충전 자체에 두 게임 재화를 요구하지 않는다. 기본 제공 아바타·기존 보유 아이템의 장착·기존 소유권을 새 복합 가격으로 재구매시키지 않는다. 신규 상품 목록·금액·할인·코인 병행/전환·기존 구매자의 적용 범위는 가격 계약에서 결정한다. 코인 잔액·원장은 보존한다.

## 2. 황금붕어빵력의 획득 경로 — DEC-022/026 확정

1. **실제 인앱구매 충전**: 기존 Google Play 상품 ID·구매 토큰 검증·서버 지갑/지급 기록을 유지한다.
2. **손님 판매 완료 보상**: 판매를완료하면드물게획득. 사용자가특별구매기회가아니라보상이라고확인했다.
3. **보상형 광고**: 사용자가선택한정상보상시청으로하루최대2회획득. 지급량/SDK·일일경계는미정이며 [광고계약](11_하루2회보상형광고.md)을따른다.

**판매 만족도는 별 5개가 만점**이다. 손님의 요구에 맞는 제품을 제공해 만족도가 높아질수록 황금붕어빵력 드롭 확률이 올라간다. 다른 조건이 같다면 높은 만족도에서 드롭 확률이 더 높아야 하며, 정확한 확률표는 미정이다. 별5개도 확정 지급이나 100% 확률을 뜻하지 않는다.

일반 판매 대금의 통화/금액은 여전히 미정이며 희귀 황금 보상과 별도로 관리한다. 별점 최저값·표시 단위·산정식·요구 항목별 가중치, 보상 확률·지급량·상한/쿨다운·적용되는 판매/손님·취향/신선도 영향은 미정이다. 재고 판매/즉석 판매 중 어느 판매에 적용되는지도 확정 전 표에 임의 포함/제외하지 않는다. 미완료 주문·취소·중복 요청을 새로운 판매 완료로 세지 않는다.

희귀 보상은 판매 ID에 연결해 한 번만 확정한다. 서버 지갑에 기록하고 재접속·결과 창 재진입·저장 실패 재시도로 재추첨/재지급하지 않는다. 오프라인 판매도 연결 후 서버 검증·1회 추첨하는 심사 대기 정책은 확정됐다. 실제 판매 증거·검증/대기복구의 상세 프로토콜은 결정 필요다. 클라이언트가 자체 추첨한 값으로 서버 권위 지갑을 임의 증액하는 구조를 확정하지 않는다.

## 3. 만렙 50 출시 — DEC-023 확정

첫 릴리즈의 최대 레벨은 **Lv.50**이다. 기존 코드의 offline-v1 Lv.1~10은 현재 구현이며 새 출시 목표와 구분한다. Lv.10이 최종 레벨·엔딩·릴리즈 완료라는 과거 목표는 최신 기획의 완료 기준이 아니다.

Lv.1~50 성장 요구량·단계별 보상·주문 종류/수량·레시피 개방 간격·진입 기능을 연결한 표가 필요하지만 수치는 미정이다. 레벨마다 레시피를 지급하지 않는 기존 확정은 유지한다. 레벨이 오를수록 주문 종류와 수량이 증가하는 방향도 유지한다. 만렙 도달 이후 반복 목표·보상과 환생 진입/초기화 정책은 별도로 결정한다.

기존30회 시작×1.5 직접 탭 목표는 **Lv.2~10까지만 있는 과거 밸런스 초안**이다. 이를 Lv.50까지 그대로 연장하거나 Lv.11~50 요구량을 임의 생성하지 않는다. 자동 생산과 복합 구매·희귀 보상·주문 성장·해금 간격을 함께 검증한 뒤 전체 곡선을 정한다. 게임 레벨50은 스킬 단계/최대 구매 수50을 뜻하지 않는다.

## 4. 꾸미기·도감·친구의 기능 해금 — DEC-024 확정

| 기능 | 첫 상태/해금 방향 | 미정 |
| --- | --- | --- |
| 아바타 꾸미기 | 기본 제공되는 꾸미기 분류 | 처음 보유하는 외형 목록·신규 유료 상품 표 |
| 아바타 외 꾸미기 | 일정 레벨에서 분류/기능 개방 | 붕어빵 무늬/토핑·가게/배경 등 분류별 정확한 레벨·순서 |
| 붕어빵/손님 등 도감 | 일정 레벨 이상에서 해당 도감 기능 개방 | 도감별 레벨·열람/행동 게이트 범위·해금 전 기록 표시 |
| 친구 기능 | 일정 레벨 이상에서 개방 | 정확한 레벨, 로그인·온라인 등 기존 자격과의 결합 |

기능 진입 잠금과 개별 아이템 구매/소유, 레시피 획득·맛별 숙련·6구 생산 해금은 서로 다른 조건이다. 기능 개방을 이유로 상품을 무료 지급하거나 보유 레시피의 큰 틀 연습/숙련 전 즉석 판매를 막지 않는다. 초기 화면에 모든 꾸미기/도감/친구가 이미 열려 있다고 기획하지 않는다.

도감 UI가 잠겨 있어도 팥 연습→숙련→6구의 핵심 흐름이 막히지 않게 진행 데이터와 기능 접근 권한을 구분하는 설계를 제안한다. 기록 시작 시점·잠금 해제 때 누적 기록 표시 방식은 아직 결정 필요다. 해금 전에 완료된 숙련/도감을 해금 후 재완료/보상 재지급하는 것으로 추정하지 않는다.

기존 사용자의 소유 아이템·도감/친구 접근권을 새 레벨 잠금에 어떻게 이전할지, 환생으로 레벨이 낮아졌을 때 기능이 다시 잠기는지는 미정이다. 코인/유료 소유권·기존 계정·친구 데이터를 삭제하지 않는다.

## 5. 기술·저장·검수 계약

가격표는 두 재화를 독립 필드로 갖고 클라이언트/서버의 같은 버전 견적을 사용한다. 붕어빵력은 BigInt/10진 문자열 원칙, 기존 gold의 서버 숫자/지갑 구조는 보존한다. 유료 재화 경로가 관여하므로 기존 지갑/상품을 재구축하지 않고 복합 지출·판매 보상 기록을 확장하는 설계를 검토한다.

로컬 SQLite 잔액과 서버 지갑은 **단일 DB 트랜잭션으로 동시에 차감할 수 없다.** 구매 의도/요청 ID·두 비용·견적 버전·처리 단계/영수증을 기록하고, 예약/서버 확정/로컬 최종화/재동기화를 포함한 복구 가능한 프로토콜을 설계해야 한다. 네트워크 단절·서버 성공 직후 앱 종료·로컬 저장 실패·백업 복구에서도 한쪽만 최종 소모되거나 상품만 중복 지급되지 않게 검수한다. 구체 프로토콜과 미완료 구매 UI는 P1-007에서 결정한다.

판매 희귀 보상은 주문 완료·재고 소비·판매 ID와 연결하되 서버 보상 확정이 늦을 때의 처리 상태를 별도로 관리한다. 영구 반영 전 ‘획득 확정’으로 표시하지 않는다. 지급 성공 후 같은 판매 ID를 다시 추첨하지 않는다. 로그/원장/검증 근거 없이 황금 잔액을 생성하지 않는다.

새 미션 시즌/50레벨·기능 해금·가격 계약·판매 보상 이전이 필요하다. 기존 레벨·보상·구매 기록/상품 ID/지갑을 보존하며 이전 기본값과 잠금 처리 정책을 결정한다. 이번 문서 반영으로 코드나 실제 결제 상품을 바꾸지 않았다.

## 6. 첫 진입과 미정 결정 — DEC-025

두 재화가 모두 필요한 구매와 초기 황금붕어빵력 접근을 함께 검토해야 한다. 황금 잔액이 없는 신규 사용자도 팥 미디엄 기본 레시피로 구매 없이 핵심 진행한다는 답변이 확정됐다. 시작 레시피의 황금 구매 필요성을 다시 묻지 않는다. 이후 유상 스킬/상품 가격 접근성은 희귀보상·일2회광고의 미정 수급량과 함께 별도 검토한다. 광고는선택이며지급량미정이다. 시작 황금 지급·무료 상품·확정 보상·확률 보정은 사용자가 정하지 않았으므로 추가하지 않는다.

처음에는 아바타 꾸미기만 있다는 말은 **꾸미기 분류의 초기 범위**이며 큰 틀·영업 등 게임 전체를 아바타만 남기는 뜻으로 해석하지 않는다. 도감/친구 등의 정확한 해금 레벨·릴리즈 콘텐츠 수·전체 개발 시간은 미정이다.
