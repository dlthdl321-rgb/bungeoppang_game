# 상태 관리 사용법

2026-10-14 / Python 표준 라이브러리 도구. tasks.json이원본, CHECKLIST.md·진행현황.md는자동생성이다. 개정전원장/도구는ZIP에보존했다. 과거이력은수정하지않고변경전후/사유를추가한다.

## 조회·갱신

```powershell
python 1_app_development/tools/planning_tasks.py render
python 1_app_development/tools/planning_tasks.py list --status "미착수"
python 1_app_development/tools/planning_tasks.py list --blocked
python 1_app_development/tools/planning_tasks.py update P1-001 --status "진행 중" --owner "개발 담당자"
```

상태변경은실제착수/검토증거가있을때실행한다. 완료는--evidence·--verification 실행결과와선행완료필요. 차단은--block-reason필요. 도구는근거문자열의진위를보증하지못하므로담당자가검토한다.

## 시간·진행률·날짜

estimated_hours가null이면미산정이며0시간이아니다. estimate_status는미산정/개정전참고·재산정필요/확정추정등출처를구분한다. 현재기존24개101시간은참고,추가16개미산정으로전체시간은미정이다. planning_basis.estimates_need_review가true인동안시간가중진행률은제공하지않고완료작업수만표시한다. 모든예정날짜는미정. 과거날짜는보관본/이력에남긴다.

재산정시원장시간/의존/날짜/근거와planning_basis를같이갱신하고변경전후이력을남긴뒤render한다. 시간미정이나문서작성만으로작업을완료하지않는다. 작업링크→상세에서완료조건·결과·선행·관련기획/검수로이동한다.

## 최신 경제·해금 작업

40개작업상세에 [복합경제·50레벨](10_복합경제와50레벨해금.md) 링크를연결한다. 1~50레벨/기능해금·두재화가격·만족도희귀보상의정확수치와이전/복구정책을확정하기전‘완료’로바꾸지않는다. 이전32개/36AC검증은당시기록이며현재집계는재생성문서와최종보고를따른다.

## 보상형 광고 작업 관리

하루2회광고도입은DEC-026확정이며P1-008/P3-008/P6-008에서구현/검수한다. 광고SDK금지의예외를문서에서명시했지만코드/테스트/실제정책이이미변경된것은아니다. [광고기준](11_하루2회보상형광고.md)의미정을확정하고일일/중복/실패와실제SDK데이터검토증거를남겨야완료다.

## 파일 안전·복구

갱신은독점잠금→복구저널→원장/이력원자교체→파생문서생성. 여러파일전체의동시트랜잭션은아니므로진행중읽기를피한다. 비정상종료시실행PID확인후남은잠금을처리하고다음실행에서저널재생한다. 저널/이력을임의삭제하지않는다.

도구검증은--root 임시복사에서수행한다. 실제완료상태를시험으로만들지않는다. 이번실행/링크/집계검증은 [최종보고](최종검증보고.md), 게임실행은미실행이다.

## 개발·기획 분리 표시

CHECKLIST와 진행현황 상단은 tasks.json의 development_snapshot에서 생성한다. existing_code는 정적 코드 근거, planned_work는 신규 목표와 작업 ID, pending_decisions는 아직 확정하지 않은 사항이다. 실행 결과는 execution_validation에 따로 기록한다. 코드·기획 검토만으로 구현 작업을 완료로 변경하지 않는다. 재검토 시 원장과 추가 이력을 함께 보존하고 render한다.
