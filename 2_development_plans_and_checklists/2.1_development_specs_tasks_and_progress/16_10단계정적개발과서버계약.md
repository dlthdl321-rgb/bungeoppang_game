## 2. 저장과 멱등성의 구현 경계

`lib/development_rules.dart`의 숙련 `toJson/fromJson`은 **분리 모델 schema1**이다. GameState 버전을14로 올리거나 새 게임 초기값을 채택한 것이 아니다. 기본 팥 미디엄 소유는 레시피 획득 기록이며, 직접 제작 결과로 얻는 수집·연습 원장에 가짜 결과를 넣어 대체하지 않는다. 다른 맛의 최초 익힘·중복 레시피 보상은 미정이다.

숙련 복원은 완료 결과 ID의 fingerprint를 재생해 전체/연습 수집·연습량·손기술 통과량을 대조한다. 결과 재열기/재시도는 같은 ID, 다른 내용은 충돌이다. 주문은 수집만, 실패 완주 연습은 연습량에 포함, 미완료는 제외한다. 손기술의 세부 비수치 판정은 이 모델 입력이며 임의로 확정하지 않았다. 결과 원장 전체 보관 비용/압축/이전은 후속 설계다. 원장 일부만 삭제해 카운터를 유지하면 복원 검증에 실패한다.

연결 시에는 결과·진행·맛 도감 완성·6구 해금·처리 ID를 같은 저장으로 확정하고 실패 시 모두 되돌려야 한다. 현재는 순수 모델만 있으며 SQLite 원자 저장·기존 사용자 이전을 완료했다고 볼 수 없다. 구형 외형/레벨/누적을 숙련으로 바꾸지 않는다. 기존 current/backup stale save 무시·거래 전 스냅샷 복원 위험은 [13번](13_저장이전과구매복구위험검토.md)에 그대로 남는다.

## 3. 판매 증거 대기 계약 — 작성자 기술 제안

`lib/development_evidence.dart`의 `PendingRewardEvidence/RewardEvidenceOutbox`는 계정·종류(sale/rewardedAd)·ID·판정 버전·정수 JSON payload를 불변 복사한다. 키 순서가 달라도 동일 증거이며 같은 ID의 다른 내용은 거부한다. 계정별 조회는 타 계정에 증거를 이전하지 않는다. 재시도에서 증거를 삭제/재발급하거나 재추첨하지 않는다. 이 모듈에는 잔액 변경·추첨·보상 확정·증거 삭제 API가 없다.

이는 **전송 전 로컬 봉투**이고 payload의 게임 유효성을 검사하는 서버 증명이 아니다. 임의 payload를 받는 이유는 미정인 주문·만족도 판정을 여기서 확정하지 않기 위해서다. 저장된 증거의 타입·중복 검사는 게임 판매 검증을 대체하지 못한다. 로그인 계정과 연결된 증거만 취급하며 비로그인 판매의 사후 계정 귀속은 미정이다. 실제 판매를 이 모듈 때문에 로그인 전용으로 바꾸지 않았다.

서버 연결 전 최소 검증 입력 설계:

| 입력 | 확인할 내용 | 권위/미정 |
| --- | --- | --- |
| 판매/주문 ID·판정 버전 | 같은 판매의 재시도, 다른 payload 거부 | 서버가 인정할 주문/증거 발급 계약 필요 |
| 제품 ID·묶음·맛·익힘·수량 | 실제 소비·동일 제품 재사용 방지·명시 주문 충족 | 로컬 주장만으로 참이라고 인정하지 않음 |
| 제작/판매 영업일·신선도 | 제작일0, 실제 영업일 age>=5 판매 제외 | 영업 날짜키/전환·미접속 정책 필요 |
| 만족도 근거 | 명시 요구·품질·신선도 입력과 판정 버전 | 별점 산식 미정, 클라이언트 별점만으로 지급 금지 |
| 일반 대금 | 제품 소비·판매 완료·대금·대기 증거를 한 저장 | 통화/누적 편입·부분 납품 정책 미정 |

서버 결과는 pending / 검증불가 / 검증완료 미당첨 / 당첨+grant를 분리한다. 네트워크 실패는 pending 유지, 검증불가를 미당첨으로 위장하지 않는다. 서버는 판매 ID별 결과와 **미당첨도** 저장한다. 당첨/grant/황금 지갑은 같은 서버 트랜잭션이다. 검증 전 황금 선지급은 없다. 서버 결과 영속·로컬 확인·증거 보관/삭제 프로토콜은 후속이며 현재 outbox에 자동 삭제를 넣지 않았다.

덜 익음은 명시 특별 주문만 가능, 가운데3종 일반 판매·타버림 판매 불가라는 확정 범위를 유지한다. 최종 명칭/미디엄 매핑·부분 납품·보관/수확 정책을 임시 숫자로 확정하지 않았다.

## 4. 복합 구매 복구 계약 — 작성자 기술 제안

`compositeReceiptMatches`는 계정·거래 ID·견적 revision·skill·owned·quantity·buns/gold 10진 문자열·committed가 모두 일치하는지 비교한다. 양의 유상 견적만 허용한다. 인증된 서버에서 받은 영수증에 적용할 **필드 일치 검사**이며 서명 검증도 지급 허가도 아니다. 기존 로컬 구매/황금 소비 API에 연결하지 않았다.

| 사건 | 먼저 할 일 | 잔액/지급 제한 |
| --- | --- | --- |
| 의도 저장 실패 | 네트워크 요청 없이 실패 안내 | 차감/예약/상품 없음 |
| 서버 예약 성공·로컬 차감 저장 실패 | 같은 ID 조회·최종 취소 확인 | 로컬 차감 증거 없이 소비 요청 금지 |
| 서버 확정 응답 유실 | 같은 계정/ID로 조회 | 타임아웃 환불·새 거래 발급 금지 |
| committed·로컬 차감 증거 있음·지급 없음 | 영수증 전체 일치 검증 후 상품/적용기록 원자 저장 | 추가 비용 차감 금지, 저장 실패면 같은 grant 재시도 |
| committed·이미 지급 | 기존 결과 반환 | 중복 상품 지급 금지 |
| canceled·차감 증거 있음·지급 없음 | 같은 ID로 비용 복원과 복원표식을 원자 저장 | 복원 완료 표식도 확인해 1회만. 기존 bool 라우팅만으로 중복 환불 방지 완료라 할 수 없음 |
| canceled·차감 없음 | 로컬 예약 해제 | 지갑 환불 금지 |
| 결과 불명·증거 소실·계정 불일치·취소 후 지급 충돌 | 조회/복구 필요로 보류 | 임의 환불·재차감·무료 지급 금지 |

가용 붕어빵력은 예약분을 제외해야 하지만 신규 예약 저장/공유 재화 명령 차단은 미연결이다. 서버의 황금 권위와 기존 gold_*·grant·구매 토큰은 유지한다. 기존 영구 권리 복원과 반복 스킬/소비성 거래를 혼동하지 않는다. 기기 권위/증거 소실 지원/백업 보호와 재설치 복구는 결정·검수 전이다.

## 5. 광고 계약 — 확정 정책과 기술 제안 구분

확정: 로그인 계정별 하루2회, KST 자정, 서버 승인 시작일에 귀속. 광고 중 고객 대기·큰 틀·6구 타이머만 멈추고 같은 진행으로 재개한다. 영업 상태·붕어빵력 정산·서버 만료/날짜는 멈추지 않는다.

`RewardedAdSlot/rewardedAdRemaining`은 인증 서버에서 받은 스냅샷으로 표시/사전검사만 하는 순수 계산이다. 서버는 동일 계정의 날짜별 한도 확인과 슬롯 예약을 한 트랜잭션으로 해야 한다. 여러 기기가 각자 잔여1을 봐도 동시에 두 예약이 승인되면 안 된다. reserved/verifying/granted는 모두 한도를 점유한다. 기기 시계·자정 뒤 완료시각으로 이전 시도를 새 날짜로 옮기지 않는다. 로컬 스냅샷만으로 광고 시작/보상 승인하지 않는다.

기술 제안: rejectedFinal은 서버가 늦은 콜백도 영구 거절하는 최종 상태이며 그때만 슬롯을 다시 쓸 수 있다. 로컬 타임아웃/광고 닫힘은 이 상태가 아니다. 검증대기는 날짜가 지나도 같은 시도 ID/시작일로 조회한다. 업체 거래ID 재사용 방지·서명/발급자·앱/광고단위·계정/시도 토큰·시간 검증 후 consumed/grant/지갑을 원자 확정한다. SDK 콜백만으로 지급하지 않는다.

예약·검증·보상량·재시도/보관 숫자는 JSON 개발 임시값을 사용한다. SDK 확인 전 타임아웃 숫자를 근거로 자동 최종거절하지 않는다. 실제 업체/SDK·개인정보 수집/보유/제3자 제공·동의/Play 신고는 아직 미정이다. 현재 무광고 정책/차단 테스트는 그대로 유지한다.

광고 정지 사유는 attempt ID별로 중복 해제하지 않게 관리하는 안을 제안한다. 전화/백그라운드/강제종료와 겹친 구간은 세션 정책이 미정이므로 실제 타이머 모듈을 임의 연결하지 않는다. 현재 오디오 foreground 정지는 광고 세 타이머 구현의 증거가 아니다.

## 6. 검증 및 후속 결정

정적 확인: 임시 설정/생성물, Dart 문법 파싱과 상대 import 경로, 원장 의존성/완료조건 보존, 이력 기존 바이트 보존, 문서 링크, 재생성 반복 일치, 공백 오류. 결과는 tasks.json의 verification_result에 기록한다. 정적 parser는 타입 분석/컴파일/테스트가 아니다.
