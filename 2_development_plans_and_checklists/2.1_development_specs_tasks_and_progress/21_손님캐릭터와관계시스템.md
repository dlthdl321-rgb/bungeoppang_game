# 붕어빵 게임 손님 캐릭터와 관계 시스템 개발 기획

손님이 반복해서 찾아오는 익숙한 이웃이 되도록 외모, 호칭, 주문 반응, 관계 변화, 손님 간 연결을 설계한다. 캐릭터마다 표현 방식은 다르게 유지하고, 대사는 짧고 일상적인 말투로 구성한다.

원문 작성 당시에는 저장소 미반영 상태였다. 이번 개정에서 관련 기존 기획·결정·기술·저장·검수·작업 문서에 반영했다. 문서 반영과 게임 구현은 별개다. 등장 빈도, 친밀도 수치, 시스템 동작은 아래의 구현 제안값을 기준으로 조정한다.

# 1 적용 범위와 기본 방향

| 민재 | 파란 바람막이, 검은 운동 바지, 비뚤어진 헤어밴드, 운동 시계 | 러닝 초보. 가게를 반환점으로 정하고 나중에는 운동 없이도 방문 | 팥 선호. 하나 고민하다 2개 주문 | 숨을 고르고 시계를 멈춘 뒤 스트레칭 |
| 수아 | 긴 검은 머리, 연보라 카디건, 크림 천가방, 토끼 장식 | 새로 이사 온 이웃. 낯을 가리지만 익숙해지면 먼저 말을 건넴 | 슈크림 선호. 친해지면 팥도 시도 | 가방 손잡이를 쥐다가 나중에는 멀리서 손인사 |

제작 시 책가방은 노란색으로 통일한다. 이전 초안의 초록색 가방은 사용하지 않는다. 외모와 행동은 아트 제작 명세이며, 이미지 자산은 별도 제작 대상이다. 주문 수량은 성향 예시이며 실제 주문 데이터와 연결한다.

# 4 관계가 쌓이는 구조

아래 수치와 빈도는 밸런스 조정용 제안이다.

| 단계 | 친밀도 제안 범위 | 관계 표현 | 열리는 콘텐츠 |
|---|---|---|---|
| 0 첫 만남 | 0~9 | 주문과 짧은 인사 | 첫 방문 대사, 캐릭터 기록 |
| 1 낯익은 손님 | 10~29 | 평소 주문을 언급 | 재방문 대사, 취향 기록 |
| 2 동네 단골 | 30~59 | 작은 생활 이야기 | 손님 간 언급, 날씨별 변형 |
| 3 가까운 이웃 | 60~100 | 개인적인 대화와 작은 이벤트 | 그림 선물, 호칭 변경, 방문 모습 변화 |

- 정확한 주문 제공: +2.
- 주문 실수 후 요청대로 교환 완료: +1. 같은 주문의 기본 성공 +2와 중복 지급하지 않는다.
- 캐릭터의 새로운 자동 대화나 관계 이벤트를 처음 완료: +1. NPC별 영업일 최대 1회. 15장의 선택형 이벤트에는 이 보상을 중복 적용하지 않는다.
- 일반 주문과 자동 대화로 NPC 한 명이 한 영업일에 얻는 친밀도: 최대 +3. 15장의 드문 선택형 이벤트 보상은 별도로 최대 +3을 지급한다.
- 대사 다시 보기, 같은 주문의 중복 처리, 앱 재실행으로 보상을 반복 획득할 수 없다.
- 품절, 접속 공백, 영업하지 않은 날에는 친밀도를 차감하지 않는다.
- 기다림과 주문 실패는 해당 주문의 결과에 영향을 주되, 초기 구현에서는 영구 친밀도 하락을 적용하지 않는다.
- 친밀도 100은 대화 종료를 뜻하지 않는다. 단골 일상 대사를 계속 사용한다.

**적용 조정 — DEC-019 유지:** 영업 세션과 영업일은 별개다. 영업일은 KST 날짜별 실제 영업을 하루 한 번 인정하며 다음 날짜에는 명시적으로 이어간다. 종료 후 같은 날짜 재영업도 같은 영업일이므로 방문·친밀도·희귀 판정 한도를 초기화하지 않는다. 원문의 세션 단위 정의는 채택하지 않는다. 재접속만으로 새 영업일을 만들지 않는다. ‘오랜만’ 판정은 달력상의 미접속 기간 대신 마지막으로 만난 영업일로부터 3영업일 이상 지났을 때를 초기값으로 제안한다.

# 5 등장과 주문의 처리

## 5.1 등장 조건

- 첫 튜토리얼 손님으로 도윤이를 제안한다. 이후 첫 3영업일에 다른 손님을 순차 소개한다.
- 한 영업일의 새로운 캐릭터 소개는 최대 2명으로 제한한다.
- 이미 만난 단골을 매 영업일 최소 1명 우선 배정한다.
- 단골별 기본 방문은 영업일당 1회로 두고, 행사 등 별도 조건이 있을 때만 추가한다.
- 은채의 아침, 윤하의 퇴근 시간대는 게임 내 시간대 기능이 있을 때 적용한다. 기능이 없으면 인물 설정만 유지하고 현재 시간에 맞지 않는 대사는 제외한다.
- 민재는 뛰는 날과 쉬는 날을 구분한다. 평상복 방문은 친밀도 3단계 이후 사용한다.

## 5.2 주문과 대기 상태

| 상태 | 진입 조건 | 대사와 처리 |
|---|---|---|
| 입장 | 방문 확정 | 첫 방문 또는 재방문 인사 |
| 주문 전 | 메뉴 선택 중 | 취향이나 고민 대사 |
| 주문 접수 | 플레이어가 주문을 수락하는 신규 제안 | 주문 항목·수량 확인. 타이머 시작을 입장에서 수락으로 바꾸는 것은 DEC-017 충돌 검토 대기이며, 수락 대기로 무제한 정지시키지 않음 |
| 대기 | 제공 전 | 대기 대사 1회 |
| 지연 | 대기시간 70% 경과 | 지연 대사 1회와 남은 시간 표시 |
| 제공 확인 | 플레이어가 상품 전달 | 실제 맛과 수량을 주문과 비교 |
| 수정 요청 | 맛 또는 수량 불일치 | 신규 교환 제안: 1회·추가 15초는 임시 후보. 현재 전량 유효 검증은 재선택·무소비이며 유예 확장은 결정 대기. 결정 전 교환 성공 보상도 연결하지 않음 |
| 제공 완료 | 정확히 제공하거나 교환 성공 | 성공 대사, 결제와 재고 소비 확정, 친밀도 반영 |
| 품절 안내 | 접수 전에 요청 메뉴를 제공할 수 없음을 안내 | 품절 대사. 대체 선택 기능은 후속 구현 |
| 시간 초과 | 제한시간 또는 수정 유예 종료 | 이탈 대사와 주문 종료 |

기존 타임어택이 있으면 기본 대기 제한시간은 그 설정을 재사용한다. 친밀도에 따라 무제한 대기하지 않는다. 기다림 대사의 부드러운 말투가 타이머 정지를 의미하지 않도록 주문창에 남은 시간을 보여준다.

**적용 조정 — DEC-006 유지:** 접수 후 앱을 닫아도 거래는 자동 완료되지 않는다. 앱 이탈 동안 손님·큰 틀·6구 타이머는 정지·복원한다. 재접속 시 이탈 시간을 손님 시간 초과로 소급하지 않는다. 원문의 경과시간 만료안은 기존 사용자 결정과 충돌하므로 적용하지 않는다. 이미 시간 초과한 손님의 대사를 재접속 때 연속 재생하지 않는다.

## 5.3 재고와 취소

- 제공 대상은 기존 기획의 주문 즉시 제작 상품 또는 미리 보유한 유효 재고다.
- 주문만 접수했다고 재고를 소비하지 않는다. 제공 완료 시 차감한다.
- 실패 후 교환 과정에서 상품을 어떻게 회수할지는 기존 상품 판정 규칙을 사용한다. 회수 상품으로 재고가 늘어나거나 동일 상품이 중복 사용되지 않게 한다.
- 주문 취소로 제작 중인 상품을 자동 삭제하지 않는다. 완성 후 재고 처리와 신선도는 기존 생산 규칙을 따른다.
- 실제로 먹은 뒤 반품하는 연출은 사용하지 않는다. 주문 실수는 먹기 전 확인으로 표현한다.
- 포장 분리, 바삭함 선호 등은 처음에는 연출과 대사 정보다. 해당 판정 시스템이 없으면 숨은 실패 조건으로 사용하지 않는다.

# 7 공통 대사 선택 규칙

1. 이벤트 종류를 먼저 판정한다. 주문 실수 순간에 날씨 대사가 대신 나오지 않게 한다.
2. 같은 이벤트 안에서 맛, 수량, 시간대, 날씨, 친밀도, 만난 손님, 완료 이벤트 조건을 검사한다.
3. 조건을 만족한 후보 중 최근에 사용하지 않은 대사를 우선한다.
4. 후보가 없으면 같은 이벤트의 캐릭터 기본 대사로 돌아간다.
5. 기본 대사도 없으면 공통 대사를 사용한다. 다른 이벤트의 대사를 임의로 가져오지 않는다.

| 공통 상황 | 대체 대사 |
|---|---|
| 입장 | 안녕하세요. 붕어빵 주문할 수 있을까요? |
| 대기 | 제 것 나오면 알려주세요. |
| 지연 | 얼마나 더 기다리면 될까요? |
| 실수 | 주문한 것과 다른 것 같아요. 확인 부탁드려요. |
| 성공 | 감사합니다. 잘 먹을게요. |
| 교환 완료 | 네, 맞아요. 바꿔주셔서 감사합니다. |
| 품절 | 아쉽네요. 다음에 다시 올게요. |
| 시간 초과 | 지금은 가봐야겠어요. 다음에 들를게요. |

- 입장 시 첫 방문과 오랜만 인사는 둘 중 하나만 출력한다.
- 한 주문에서 입장, 대기, 결과 대사를 기본으로 하며 지연 대사는 필요할 때만 추가한다.
- 특별 대화는 기본 대기 대사를 대체하거나 제공 완료 후 배치한다.
- 날씨 대사는 입장 또는 여유 대화에서 사용한다.
- 스토리 이벤트 중에는 주문 타이머를 잠시 멈춘다. 일반 대기 말풍선은 타이머를 멈추지 않는다.
- 자동 대화는 연출을 넘겨도 이벤트 완료와 보상을 동일하게 처리한다. 15장의 선택형 대화에서 응답 전 배웅은 +0이고, 응답 확정 후 반응 연출을 넘길 때는 선택 보상을 유지한다.
- 대사에 포함된 주문 맛과 수량은 UI와 같아야 한다. 친밀 대사에서 팥 추가를 제안하면 주문 확정 전에 반영한다.
- 주문 후보는 해금된 레시피에서만 고른다. 제공 가능한 기본 맛이 하나뿐이면 그 맛의 주문과 대사를 사용한다.
- 여러 손님이 없을 때는 ‘오늘 손님이 많네’를 제외한다. 바삭함, 긴 꼬리 등 구체적 성공 대사에는 해당 연출 조건을 연결하고, 판정이 없으면 ‘감사합니다. 잘 먹을게요.’ 계열의 중립 성공 대사를 쓴다.
- 최근 3개 대사 ID를 NPC별로 저장한다. 후보가 하나뿐일 때는 반복을 허용한다.
- 개인 사연 대사는 첫 사용을 기록하고 이후에는 일상형 변형을 사용한다. 본가 방문이나 시험 종료를 매번 새 사건처럼 반복하지 않는다.

# 8 표정과 행동

| 캐릭터 | 대기 | 기쁨 | 아쉬움 | 가까워진 뒤 변화 |
|---|---|---|---|---|
| 윤하 | 가방 끈을 고쳐 멤 | 어깨 힘을 풀고 작게 웃음 | 메뉴판을 한 번 더 봄 | 먼저 목례하고 휴대전화를 내려둠 |
| 도윤 | 발뒤꿈치를 들썩임 | 붕어빵을 눈높이로 듦 | 가방 끈을 잡고 발끝을 봄 | 공책을 펼쳐 보여줌 |
| 막례 | 손가락으로 수량을 셈 | 눈가에 주름이 잡히며 웃음 | 손을 가볍게 내저음 | 자기 몫을 가게 앞에서 먹음 |
| 서진 | 수첩에 스케치 | 수첩을 덮고 음식에 집중 | 연필로 수첩 모서리를 두드림 | 완성한 그림을 꺼냄 |
| 태오 | 카메라 설정을 만짐 | 촬영을 잊고 한입 먹음 | 카메라 덮개를 닫음 | 카메라를 가방에 넣고 방문 |
| 은채 | 눈을 잠깐 감음 | 봉투를 두 손으로 감쌈 | 눈을 비비지 않고 천천히 깜빡임 | 쉬는 날 또렷한 눈으로 먼저 인사 |
| 민재 | 가벼운 스트레칭 | 시계를 멈추고 웃음 | 시계와 틀을 번갈아 봄 | 평상복으로 방문 |
| 수아 | 가방 손잡이를 쥠 | 봉투를 보며 작게 웃음 | 잠깐 머뭇거림 | 멀리서 손인사 |

초기 구현은 기본, 기쁨, 아쉬움의 정적 표정 3종을 우선한다. 관계 변화 행동과 복장 변형은 후속 자산으로 추가한다.

## 9.2 동행 대화

동행 대화는 두 인물을 모두 만났고 각 친밀도 2단계 이상일 때 후보가 된다. 영업일당 최대 1회로 제안한다. 기본 방문 배정에서 두 인물을 함께 등장시키며 거래는 각자의 주문 ID로 처리한다.

| 조합 | 대화 |
|---|---|
| 막례와 도윤 | 막례: 도윤아, 오늘도 질문 보따리 들고 왔니? / 도윤: 오늘은 세 개밖에 없어요. 물어보다 늘어날 수도 있고요. |
| 막례와 윤하 | 막례: 오늘은 얼굴이 좀 폈네. / 윤하: 금요일이잖아요. 붕어빵도 있고요. |
| 서진과 도윤 | 도윤: 제 안경 너무 동그랗게 그렸어요. / 서진: 실제로도 동그란데. / 도윤: 그래도 좀 멋있게요. |
| 태오와 도윤 | 도윤: 형! 먹지 말고 사진! / 태오: 아, 맞다. 너 없으면 오늘도 놓쳤겠다. |
| 막례와 태오 | 막례: 사진쟁이 총각, 오늘은 잘 찍었어? / 태오: 네. 할머니 몫은 식기 전에 드릴게요. |
| 막례와 민재 | 막례: 최 씨, 또 한 바퀴야? / 민재: 이번에는 진짜 마지막이에요. 여기까지만요. |
| 은채와 민재 | 민재: 이제 퇴근하세요? / 은채: 네. 이제 뛰러 가세요? / 민재: 아뇨. 오늘은 먹으러만 왔어요. |
| 윤하와 수아 | 수아: 늘 같은 시간에 오시네요. / 윤하: 수아 씨도요. 이제 여기서 만나면 시계 안 봐도 되겠어요. |
| 서진과 태오 | 태오: 작가님 그림은 붕어빵이 안 식어서 좋겠어요. / 서진: 대신 못 먹어요. |
| 막례와 수아 | 막례: 동네 살 만해요? / 수아: 네. 이제 인사할 사람이 생겨서요. |

금요일 대사는 게임 내 요일이 금요일일 때만 사용한다. 요일 기능이 없으면 윤하의 대사를 ‘오늘은 일이 일찍 끝났거든요. 붕어빵도 있고요.’로 바꾼다.

동행 기능이 없는 초기 버전에서는 위 대화를 재생하지 않고, 6장의 이웃 언급 대사로 관계를 전달한다.

# 10 친밀도 이벤트

| 캐릭터 | 조건 | 이벤트 | 완료 후 변화 |
|---|---|---|---|
| 윤하 | 3단계, 성공 제공 3회 이상 | 평소 주문을 기억하는 짧은 대화 | 먼저 안부를 묻는 대사 해금 |
| 도윤 | 2단계 | 간식 지도 공개 | 지도 관련 대사 해금 |
| 막례 | 3단계 | 처음으로 자기 몫도 주문 | 가게 앞에서 먹는 행동 해금 |
| 서진 | 3단계, 그림 대화 경험 | 가게 그림 선물과 호칭 대화 | 그림 기록, 서진 씨 호칭 허용 |
| 태오 | 3단계 | 카메라 없는 방문 | 촬영 없는 일상 대사 해금 |
| 은채 | 3단계 | 쉬는 날 낮 방문 | 휴일 방문 상태 해금 |
| 민재 | 3단계 | 운동복 아닌 평상복 방문 | 산책 손님 상태 해금 |
| 수아 | 3단계, 막례와 수아 모두 만남, 막례 2단계 이상 | 우리 동네 수아 씨 | 표시 명칭 변경 |

수아 이벤트는 두 인물이 함께 등장하는 방식으로 구현한다. 동행 시스템이 아직 없어도 해당 장면만 별도 이벤트로 연출할 수 있다. 조건을 만족해도 자동 변경하지 않고 장면 완료 시 변경한다.

### 수아 호칭 변경 대사

막례: 새로 온 아가씨라니. 이제 우리 동네 수아 씨지.

수아: 저 이제 길 안내도 할 수 있어요. 붕어빵집 가는 길은 특히 잘 알고요.

완료 처리: 수아의 표시 명칭을 ‘우리 동네 수아 씨’로 변경하고 완료 플래그를 저장한다. 메뉴, 도감, 현재 말풍선 이름표에 같은 명칭을 적용한다. 내부 ID와 기존 기록은 유지한다.

### 서진 호칭 대화

서진: 작가님이라고 부르시면 아직도 누굴 찾으시는 건가 싶어요.

사장님: 그럼 서진 씨라고 불러도 될까요?

서진: 네. 여기는 그림 얘기 안 하고 와도 되는 곳이면 좋겠어요.

완료 처리: 사장님의 개인 호칭을 ‘서진 씨’로 변경한다. 화면 표시 명칭은 ‘옥탑방 오 작가’를 유지한다.

# 14 확인 항목

- 8명의 내부 ID는 같게 유지되고, 표시 명칭만 기획에 따라 바뀐다.
- ‘정윤하 씨’, ‘김도윤’처럼 참고 실명이 일반 화면에 일괄 노출되지 않는다.
- 수아의 호칭은 이벤트 완료 전후에 정확히 구분된다.
- 사장님은 기본적으로 ‘민재 씨’, 막례 할머니는 ‘최 씨’라고 부른다.
- 도윤이의 책가방은 노란색이다.
- 일반 대사를 읽는 동안 타이머가 임의로 멈추지 않으며 스토리 연출에서는 멈춘다.
- 주문과 다른 맛, 수량, 대사가 섞이지 않는다.
- 접속하지 않은 기간에 친밀도가 줄지 않는다.
- 영업 중 오프라인 생산이 자동 주문 성공이나 자동 친밀도 증가로 이어지지 않는다.
- 그림 선물, 호칭 변경, 최초 사연은 중복 완료되지 않는다.
- 휴일 은채와 평상복 민재가 근무·운동 중 대사를 말하지 않는다.
- 태오의 촬영과 소개 글은 이야기 연출로만 동작한다.
- 대사를 건너뛰거나 다시 보아도 주문 및 이벤트 보상이 중복 지급되지 않는다.
- 품절과 기다림에 캐릭터의 개성은 남지만 모욕이나 죄책감 유도 대사는 나오지 않는다.

# 15 드문 선택형 대화 이벤트

## 15.1 목적과 등장 빈도

평소에는 손님의 말을 듣고 주문을 처리하지만, 아주 가끔 손님이 사장님의 대답을 기다리는 순간을 만든다. 사장님이 어떤 말로 응답했는지에 따라 친밀도와 다음 방문의 한마디가 달라진다. 선택형 대화는 기존 10장의 관계 이벤트와 구분하며, 관계 이벤트 해금의 필수 정답 시험으로 사용하지 않는다.

다음 수치와 발생 확률은 초기 밸런스 제안이다.

| 항목 | 적용 규칙 |
|---|---|
| 최초 후보 시점 | 7번째 영업일부터. 튜토리얼과 첫 방문에서는 발생하지 않음 |
| 발생 간격 | 전체 손님을 합쳐 최소 5영업일 간격. 예: 7일에 발생했다면 다음 후보는 12일 |
| 판정 단위 | 조건을 만족한 손님에게 정확한 주문 제공을 마친 직후, 해당 영업일 최초 1회만 판정 |
| 발생 확률 | 유효 후보가 있는 날 12%. 실패한 날 추가 손님으로 다시 추첨하지 않음 |
| 영업일당 제한 | 최대 1회. 일반 관계 이벤트나 동행 대화가 나온 날에는 선택형 이벤트를 발생시키지 않음 |
| 손님별 차이 | 아래의 인물별 조건을 모두 만족해야 공통 확률 판정 후보가 됨 |
| 반복 | 응답을 선택한 개별 사건은 다시 발생하지 않음 |
| 답하지 않고 넘김 | 친밀도 변화 없음. 동일 사건은 10영업일 이후 조건을 다시 만족하면 후보가 될 수 있음 |
| 접속 공백 | 실제 달력상의 날짜나 미접속 기간으로 희귀도를 판정하지 않음 |
| 재실행 | 같은 영업일의 판정 결과와 활성 이벤트를 저장해 재추첨하지 않음 |

희귀한 확률은 등장 간격과 함께 적용한다. 일정 영업일마다 반드시 발생하는 보장 규칙은 초기 구현에서 두지 않는다. 플레이 테스트에서 지나치게 보기 어렵다면 확률이나 간격을 조정한다.

## 15.2 선택 화면과 보상

손님의 첫 말을 보여준 뒤 사장님 대사 3개와 ‘지금은 미소로 배웅한다’ 버튼을 제공한다. 선택 제한시간은 없다. 정답 표시나 친밀도 숫자는 선택 전에 보여주지 않는다. 세 대사 모두 일상적으로 할 수 있는 말이며, 손님의 현재 관심사에 얼마나 맞는지가 차이를 만든다.

| 결과 | 친밀도 | 기록 |
|---|---|---|
| 현재 마음을 구체적으로 알아주는 응답 | +3 | 선택 ID, 손님 반응, 후일담 플래그 |
| 다정한 공감이나 관심 | +2 | 선택 ID, 손님 반응, 후일담 플래그 |
| 짧은 일상적 응답 | +1 | 선택 ID, 손님 반응, 후일담 플래그 |
| 미소로 배웅 | +0 | 이번 회차 보류 기록. 영구 완료하지 않음 |

- 선택형 보상은 일반 영업일 친밀도 상한 +3과 별도로 1회 지급한다. 이벤트가 있는 날 NPC 한 명의 총 증가량은 최대 +6, 전체 친밀도는 100을 넘지 않는다.
- 선택형 이벤트는 일반적인 ‘새 대화 최초 완료 +1’을 추가 지급하지 않는다.
- 답하지 않았다고 실망하거나 화내는 대사는 사용하지 않는다.
- 친밀도가 이미 100이어도 이벤트와 선택별 후일담은 볼 수 있다.
- 연출 애니메이션이나 이미 선택한 뒤의 손님 반응을 넘겨도 보상은 유지한다. 선택 전에 배웅하는 것은 +0이다.
- 대화와 선택창이 열리면 다른 손님의 대기시간과 주문 생성도 정지한다. 생산, 신선도 등 영업 시뮬레이션도 함께 정지해 대화 시간을 이익이나 손실로 이용하지 못하게 한다. 닫은 뒤 정지 시간을 차감하고 재개한다.
- 앱을 닫으면 활성 이벤트와 멈춘 영업 상태를 저장한다. 재접속 시 이어서 선택하거나 배웅할 수 있고, 이 대화 정지 구간에는 오프라인 생산을 추가하지 않는다.
- 금전 지출, 상품 무료 제공, 실제 사진 촬영, 자유 입력 문장은 요구하지 않는다.

아래 A·B·C와 점수는 기획용 표기다. 실제 선택지는 순서를 섞어 보여주고 안정적인 선택 ID로 저장한다.

## 15.9 민재 씨의 이벤트 한 바퀴를 못 채운 날

이벤트 ID: choice_minjae_01

발생 조건: 민재 5회 이상 방문, 러닝 복장 방문을 3회 이상 봄, 친밀도 20 이상, 평상복 첫 방문 이벤트 완료 전일 때. 이번 방문은 운동복이지만 ‘코스 중간에 돌아옴’ 상태를 이벤트 주문 생성 시 부여한다. 실제 운동량이나 건강정보는 수집하지 않는다.

손님: “오늘은 한 바퀴 못 채웠어요. 중간에 돌아왔는데 붕어빵은 먹고 싶더라고요.”

| 선택 | 사장님의 대사 | 민재의 반응 | 친밀도 |
|---|---|---|---|
| A | 여기는 한 바퀴 다 돌아야 들어올 수 있는 곳은 아니에요. | “그러네요. 제가 혼자 입장 조건을 만들었네요.” | +3 |
| B | 오늘은 여기까지 산책한 걸로 해요. | “좋아요. 돌아갈 때도 천천히 걸어야겠어요.” | +2 |
| C | 그럼 오늘도 팥으로 드릴까요? | “네! 팥 생각은 끝까지 똑같더라고요.” | +1 |
| 배웅 | 봉투를 건네며 가볍게 웃는다. | 민재는 시계를 끄고 봉투를 받아 든다. | +0 |

후일담: A는 “오늘은 입장 조건 없이 왔습니다.” B는 “오늘도 산책 코스로 왔어요.” C는 “오늘도 팥이요. 취향은 꾸준합니다.”를 출력한다. 후일담은 러닝을 쉬는 방문 상태와 함께 생성한다. 선택 결과와 무관하게 기존 평상복 이벤트는 해금 가능하다.

## 15.10 수아 씨의 이벤트 기억해주는 가게

이벤트 ID: choice_sua_01

발생 조건: 수아를 서로 다른 영업일에 3회 이상 만남, 슈크림 주문 성공 2회 이상, 친밀도 10 이상, 마지막 만남 이후 3영업일 이상 경과한 재방문, 수아 호칭 변경 이벤트 완료 전일 때. 다른 손님들과 영업한 날을 기준으로 하며, 미접속으로 사건을 강제하지 않는다.

손님: “며칠 만에 왔는데 기억하시네요. 아직 동네에서 제 이름 아는 곳이 별로 없어서요.”

선행 연출로 사장님이 “수아 씨, 오랜만이에요.”라고 인사한 뒤 선택창을 연다. 화면 표시 명칭은 아직 ‘새 이웃 수아 씨’다.

| 선택 | 사장님의 대사 | 수아의 반응 | 친밀도 |
|---|---|---|---|
| A | 그럼 여기는 이름 아는 곳 하나 생긴 거네요. 반가워요, 수아 씨. | “네. 저도 여기 오면 좀 편해요.” | +3 |
| B | 슈크림 좋아하시는 것도 기억해요. | “맞아요. 오늘도 같은 거 먹고 싶었어요.” | +2 |
| C | 다음에도 편하게 들러주세요. | “네. 산책할 때 또 올게요.” | +1 |
| 배웅 | 눈을 맞추고 반갑게 웃는다. | 수아는 가방 손잡이에서 손을 놓고 작게 웃는다. | +0 |

후일담: A는 “이름 아는 곳에 또 왔어요.” B는 “기억해주신 슈크림, 오늘도 먹으려고요.” C는 “산책하다가 들렀어요. 안녕하세요.”를 출력한다. 이 선택만으로 호칭을 변경하지 않는다. ‘우리 동네 수아 씨’는 기존 관계 이벤트에서 따로 변경한다.

## 15.11 후일담과 관계 이벤트의 순서

- 후일담은 다음 조건에 맞는 방문에서 1회 출력하고 소비한다. 복장이나 주문 조건이 맞지 않으면 대기한다.
- 입장형 후일담은 일반 재방문 인사를 대체한다. 주문 내용에 영향을 주는 후일담은 방문과 주문 생성 단계에서 적용한다.
- 실제 대화가 이뤄진 것처럼 기록하는 것은 A·B·C를 선택했을 때뿐이다. 미소로 배웅한 경우 선택별 후일담을 만들지 않는다.
- 같은 영업일에 후일담과 새 선택형 이벤트를 겹치지 않는다.
- 순서는 미완료 활성 대화 재개, 조건을 만족한 기존 관계 이벤트, 선택 후일담, 새 선택형 이벤트, 일반 대화 순이다.
- 이 사건을 본 적이 없어도 그림 선물, 평상복 방문, 수아 호칭 변경 같은 기본 관계 이벤트는 진행할 수 있다.
- 기존 단계가 이미 높은 저장 데이터를 불러오면, 이전 상황으로 돌아가야 하는 선택 사건은 비활성화한다. 예: 이미 그림을 선물했다면 서진의 선물 전 고민은 나오지 않는다.

## 15.12 구현 데이터

| 구분 | 필드 | 내용 |
|---|---|---|
| 이벤트 정의 | choice_event_id, npc_id | 사건과 손님 식별 |
| 이벤트 정의 | required_flags, forbidden_flags | 선행 대화, 주문 이력, 이후 사건과의 충돌 방지 |
| 이벤트 정의 | min_affinity, min_visits | 손님별 최소 조건 |
| 이벤트 정의 | order_context, visit_variant | 맛, 수량, 근무와 휴일, 운동 상태 |
| 이벤트 정의 | prompt, choices | 손님의 말, 선택 ID, 사장님 대사, 손님 반응, 친밀도 |
| 이벤트 정의 | followup_by_choice | 선택별 다음 방문 대사와 필요한 주문 상태 |
| 이벤트 저장 | offered_business_day | 마지막 제시 영업일과 보류 재등장 계산 |
| 이벤트 저장 | completed_choice_events | 응답 완료 사건과 선택 ID |
| 이벤트 저장 | pending_followups | 아직 보지 않은 후일담 |
| 이벤트 저장 | rare_roll_business_day, rare_roll_result | 영업일당 추첨 1회와 재실행 방지 |
| 이벤트 저장 | last_choice_event_business_day | 전체 5영업일 간격 |
| 이벤트 저장 | active_choice_event | 선택 전, 선택 후 반응, 닫기 상태 |
| 이벤트 저장 | affinity_reward_applied | 동일 사건 보상 중복 방지 |
| 이벤트 저장 | simulation_paused_at, accumulated_pause | 대화 중 영업 시간 정지와 복원 |

choice_event는 일반 story와 다른 이벤트 종류로 추가한다. 선택 확정, 친밀도 반영, 완료 기록, 후일담 예약을 한 번에 저장한다. 선택 후 강제 종료해도 선택이 바뀌거나 보상이 재지급되지 않아야 한다.

## 15.13 확인 항목

- 8명 모두 서로 다른 인물별 조건이 있어야 한다.
- 같은 영업일에 여러 손님을 받거나 앱을 재실행해도 희귀 확률을 다시 굴리지 않는다.
- 5영업일 간격과 인물별 조건을 모두 통과해야 발생한다.
- 선택지 세 개와 미소 배웅이 있고, 선택 전 점수는 노출하지 않는다.
- +3, +2, +1, +0 결과와 다음 방문 대사가 실제 선택 ID에 맞는다.
- 이벤트 보상은 기존 +3 상한에 잘려 사라지지 않으며, 일반 최초 대화 +1이 중복 붙지 않는다.
- 배웅, 선택 후 연출 넘기기, 이야기 다시 보기를 구분한다.
- 대화 중 다른 주문, 생산과 신선도 시간이 멈추고 재개된다.
- 호칭 변경이나 그림 선물이 먼저 끝난 저장에서 과거 상황 사건이 튀어나오지 않는다.
- 미접속, 배웅, 어느 응답을 고르든 친밀도 하락과 핵심 콘텐츠 차단이 없다.
