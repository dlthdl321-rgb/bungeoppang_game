# 신규 게임 연결과 사용자 결정 반영

> 이 문서는 작성 당시 소스/검토 기록이다. 이후 첨부에서 추가된 [손님·관계 목표](21_손님캐릭터와관계시스템.md)는 아직 구현하지 않았으며, 아래 기존 구현 범위/검증 결과가 신규 NPC·친밀도·선택 이벤트까지 포함한다는 뜻은 아니다.

후속 변경은 [19번 구매 원자 저장·복구](19_구매원자저장과복구후속.md)를 따른다. 아래 schema1/자동0·상점 미리보기 설명은 이 기록 시점의 상태다.

2026-10-16 / 기준 `bf4f37f` 이후. **소스 작성·정적 검토 결과이며 앱 실행·컴파일/타입 분석·Flutter/서버 테스트·빌드·실기기·실제 결제/서비스 검수는 미실행**이다.

## 1. 사용자 확정과 범위

[결정 취합](2.1.1_game_rules_and_decisions/00_결정취합.md)의 이번 두 묶음 답변을 기존 DEC에 반영했다. 새 DEC/REQ/작업/AC ID를 만들지 않았다.

- 기존 사용자는 없고 신규 게임이다. 구형 레벨/권리 환산은 필수 출시 대상에서 제외한다. 새 저장 손상·실패/복구·중복 보상·기기 이전 위험은 남는다.
- 코인은 신규 개념이 아니며 붕어빵력·황금붕어빵력 두 재화다. 구형 코인 미션은 서버 검증 후 황금 보상으로 재설계한다. 로컬 황금 생성은 금지다.
- 초기 보유는 팥 미디엄만, 팥도 연습5종 AND 연습량 AND 손기술을 채워 숙련한다. 5명칭/중간 미디엄·두 반죽/속 방향/일반 판매 익힘의 손기술 구조가 확정됐다.
- 6구는 획득 AND 숙련한 맛만 배정하며 계속 익는다. 직접 수확만 제품 지급, 덜 익음도 수확, 탄 칸은 직접 폐기한다. 큰 틀 연습 결과는 보관/버리기 선택, 주문 제품은 재고에 넣고 손님에게 판매한다.
- 영업일은 KST 하루1회 인정, 날짜가 바뀌면 명시 이어가기. 앱 이탈에는 고객·큰 틀·6구 정지/복원, 붕어빵력은 열린 영업의 기존8시간/50% 정산. 가려진6구만 정지하며 전경 큰 틀 중에도 손님 대기는 계속된다.
- 준비 제품은 다음 실제 영업일에 최초1회 나이0 귀속. 결과 재열기/저장 재시도로 신선도를 새로 만들지 않는다.
- 손님에게 전량을 한 번에 판매한다. 일반 대금은 붕어빵력과 누적에 합산하며 품질·신선도 별점은 대금에 다시 곱하지 않는다. 덜 익음 특별 주문은 명시 요구 충족 시 품질 실패 감점하지 않는다. 실패/취소는 재고 유지·예약 해제, 판매/대금/황금 기회/벌금0이다.
- 계정당 활성 진행은 한 기기. 이전/백업 근거와 미정산을 대조하며 증거 소실 시 복합 구매를 보류하고 일반 오프라인 플레이는 유지한다.
- 신규 Lv.1~50은 누적/현재 레벨 추가 탭/판매 조건 AND·버튼 승급·1회 보상. 초기 환생은 숨기고 Lv.50 이후 분점은 후속이다. 8종 추천 목록은 채택하지 않았으며 후속 답변으로 슈크림·초코만 추가 획득 대상으로 확정했다. 초기 보유는 팥만이고 두 추가 맛은 상점 OR 미션, 나머지 맛은 후속이다.
- 광고는 AdMob 보상형·SSV 기준 준비. 현재 SDK는 설치하지 않았고 실제 식별자/수집·동의/검증을 확정하지 않았다.

## 2. 조각 모델에서 실제 진입점으로 연결한 소스

main.dart는 공통 설정을 읽고 WorkshopController/SqliteWorkshopRepository를 초기화해 GameApp.workshop에 전달한다. 신규 기본 화면은 WorkshopPage다. GameApp.workshop을 지정하지 않는 구형 화면/테스트 경로는 남겼지만 신규 main은 코인 지갑/코인 교환/구형 환생 UI로 진입하지 않는다.

기존 GameController는 설정·로그인·기존 서버 황금 지갑/IAP를 연결하는 포트로 사용한다. 구형 클리커 buns/level/coin 상태는 신규 플레이 진행의 권위가 아니다. 신규 플레이 진행은 **todays_bungeoppang_workshop.db**, snapshots current/backup, aggregate schema1이다. 설정/기존 계정 포트의 GameState v13과 구분한다. 기존 앱 DB를 파괴하거나 구형 자산을 황금으로 로컬 환전하지 않는다.

## 3. 저장·타이머·재시도에서 지킨 조건

- 단계 완료·결과 숙련/도감·보관·수확·판매·승급은 집계 상태를 한 번 저장한다. 저장 실패 시 같은 저장 전 상태로 되돌리고 다음 경제 명령을 막아 재읽기로 내구 결과를 확인한다. DB에 성공했는데 응답만 실패한 경우도 재읽기 전 새 결과를 만들지 않는다.
- 재고 소비·판매 ID·일반 대금·누적·황금 대기는 같은 스냅샷이다. 심사 대기는 확정 황금 지갑/가용액에 포함되지 않는다. 새 게임 상태에는 coin/coins 필드가 없다.
- 같은 날짜의 재영업은 영업일+0, 현실 공백 뒤 이어가기는+1, 제작일 나이0/age>=5 소멸이다. 준비품은 실제 영업 인정 전 판매 재고가 아니고 같은 결과의 귀속을 다시 갱신하지 않는다.
- 입력 시 단조 시간 경과를 먼저 반영해 마감된 주문의 판매를 차단하고, 꺼내기 시각 익힘을 고정한다. 보통 저장 중 시간은 다음 틱에 이어 반영하며 이탈/복구 오류 중에는 정지한다.
- 실제 굽기 소스를 GameAudio에 전달한다. 큰 틀·가림·영업 중단·이탈·오류와 6구 소스를 분리하고 동일 활성 여부 반복으로 플레이어 명령을 쌓지 않는다. 실제 청음은 하지 않았다.
- 단계/수확 결과는 고정 ID, 6구 맛·회차·경과는 직렬화한다. 숙련 확정은 당시 revision/요구량/결과 ID를 보존해 임시 숫자를 늘렸다고 이미 얻은6구를 재잠금하지 않는다.
- 체크포인트는 공통 임시 설정 checkpoint_ms(현재1000)다. 프레임/탭마다 저장하지 않으며 강제 종료 시 마지막 체크포인트 이후 연속 입력/탭은 손실될 수 있다. 무손실이라고 주장하지 않는다.
- 복구 화면은 저장을 자동 삭제하거나 구형 게임 UI로 우회하지 않는다. 과거 backup의 자동 복원·진행 이전은 서버 보호 기록 대조 전 연결하지 않았다.

## 4. 현재 화면에서 아직 이용할 수 없는 것

이 문서는 **모든 게임 구현 완료**를 뜻하지 않는다. 소스상 연결한 신규 기본 경로와 아래 경계를 구분한다.

- 새 두 재화 스킬/꾸미기 실제 결제·상품 적용은 아직 연결되지 않았다. 가격 미리보기만 가능하며 구형 로컬 구매/황금 단독 구매로 우회하지 않는다. 신규 스킬이 없으므로 현재 WorkshopController의 실제 자동 생산율은0이다. BusinessProgress의 비영 생산율8시간/50% 계약은 별도 소스/미실행 테스트로 준비돼 있다.
- 미션/판매 황금은 검증 대기이며 실제 server verifier·지급 수신 확인/동기화가 남는다. earned_gold.ts는 신뢰된 검증 결과를 받는 내부 지급 코어이지 클라이언트 임의 보상 API가 아니다.
- AdMob SDK/앱ID·광고단위·SSV public key/서명/발급자/광고단위·동의 검토가 남는다. 공식 문서 `https://developers.google.com/admob/android/ssv`, `https://developers.google.com/admob/flutter/rewarded`는 이번 환경에서 CONNECT HTTP403으로 열리지 않았다. 실제 SDK 버전/검증 구현을 추정해 채우지 않았다. 문서 접근은 시도했지만 실제 광고/서비스 요청은 하지 않았다.
- 센서 스트림은 기울여 반죽 붓기/중립 정지와 속 방향 입력에 연결했고 취소 가능한 터치/화면 읽기 대체도 제공한다. 실제 센서 유량·실기기 방향·오디오·아트5종·작은 화면 검수는 후속이다. 기존 이미지 파일은 교체/삭제하지 않았다.
- 기본 레시피/연습 기록과 Lv.3 이후 5단계 도감 표시, 슈크림/초코 미션 조건 획득·맛별 숙련/6구 후보·복합 주문, 같은 손님의 명시 맛/익힘 관찰 영구 도감을 연결했다. 손님 실패/취소는 관찰을 지우지 않고 도감 보상/숨은 취향 추정도 하지 않는다. 친구/랭킹 신규 진행 연동·분점·꾸미기 실제 적용은 이번 신규 경로에 완성하지 않았다. 기존 추천8종을 창작해 넣지 않았다.

## 5. 검증과 체크리스트 처리

추가 테스트 소스는 제작/입력/터치/센서 미지원, 정산/준비품/재고/6구/품질, 신규 집계 실패 복원·전량 판매, 구매 조정·활성 진행·서버 황금 지급을 다룬다. 전부 **작성만 했고 실행하지 않았다**. 기존 테스트의 목표를 낮추거나 삭제하지 않았다.

최종 정적 확인에서 Dart 150개·TypeScript 20개·Kotlin 2개 파일의 구문과 상대 import, Python AST, 숫자/생성물, Markdown 파일 링크, 기존 원장 ID/의존성/완료조건/AC 보존·과거 이력 바이트 보존, 생성 문서 반복 일치·공백을 확인했다. 추가 테스트는 30개이며 실행하지 않았다. 원장은 총40개 중 완료1·검토 중27·차단2·미착수10이고, 과거 이력 뒤에 이번 변경29건을 추가했다. 이것은 컴파일·타입 분석·기능/회귀 테스트·실기기 검수와 다르다.

tasks.json에 이번 소스와 위 미완료 경계를 기록하고 task_history.jsonl에만 이력을 추가한다. CHECKLIST.md/진행현황.md는 planning_tasks.py render로 재생성한다. 실행 검수가 남는 작업은 완료로 올리지 않는다.
