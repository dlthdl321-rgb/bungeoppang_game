## 2. JSON v13 변경의 실제 범위

GameState.formatVersion을13으로 올리고 **오디오 설정만** 추가했다. 새 설정은 musicSelection·cookingSound·cookingVolume이며 v1~12의 기존 자산/레벨/스킬/원장/지갑 파싱을 유지한다. 구형 설정은 배경에 맞춤(auto), 생성된 굽기 기본값으로 읽는다. v13의 누락·잘못된 선택/타입/음량은 손상으로 거부한다.

새 v13은 사업 운영/숙련/재고/복합 거래 이전을 포함하지 않는다. 구형 앱은 v13을 읽지 못하므로 실제 사용자 저장에 적용하기 전 백업·업그레이드/다운그레이드 기대값을 검수해야 한다. [13번](13_저장이전과구매복구위험검토.md)의 미정 정책을 채택하거나 실제 사용자 데이터를 변환한 것이 아니다. 다음 신규 스키마 후보 값은14로 두었지만 향후 버전 확정은 별도다.

설정 저장은 큐로 직렬화하고 기존 _commit의 실패 복원 경로를 사용한다. 한 설정 변경당 한 번 저장하며 실패 시 선택/음량을 함께 복원한다. Dropdown은 컨트롤러 저장 상태를 표시한다. 초기 오디오 init 전 복원한 설정을 적용하고 비동기 소스 교체/정지/재개를 큐로 정렬했다. 실제 플러그인 경합·기기 소리 결과는 아직 검증하지 않았다.

## 3. 수치만 바꾸는 절차

1. `1_app_development/config/development_balance.json`의 조정값 수정. 확정 조건은 별도 잠금 검증.
2. 저장소 루트에서 `python 1_app_development/tools/development_balance.py` 실행.14번 표와 오디오 기본값 Dart 재생성.
3. `--check`로 설정·생성물 일치 확인. 게임 기능이 해당 원본을 소비할 때만 런타임 동작이 바뀐다.
4. 서버에 적용하는 구매가격은 서버 배포본/견적 버전이 권위다. 로컬 JSON을 고쳤다고 실제 서버 가격·IAP를 바꾸지 않는다.

## 4. 작성한 테스트 — 미실행

- development_rules_test.dart: 실제 설정 읽기, 고정 산술 fixture의 두 재화 경계/최대구매, 입력 수정 격리, 익힘 경계·5영업일, 주문/실패연습·동일ID 충돌·숙련3조건, KST 시작일, 불명 서버 결과의 비환불/증거 보류.
- independent_music_test.dart: v12 자산 보존/v13 왕복/손상 거부, 배경 독립·자동 복귀·전경 수명, 복수 굽기 소스/설정, 설정 저장 실패·겹친 저장 직렬화.
- stage12_customization_test.dart는 기존 자산/슬롯 assertions를 유지하며 저장 버전 기대값만 최신 formatVersion으로 갱신했다. 실패 회피를 위해 테스트/허용치를 낮추지 않았다.

향후 `1_app_development`에서 `flutter test test/development_rules_test.dart test/independent_music_test.dart test/stage10_feedback_test.dart test/stage12_customization_test.dart test/serialization_test.dart`와 `flutter analyze`를 수행한다. 이후 실제 SQLite 복구·Android 3채널 청음·생명주기·작은 화면/큰 글자·빠른 선택 검수가 필요하다. 이 명령은 이번에 실행하지 않았다.

## 5. 지금 멈춘 경계

- Flutter/Dart SDK가 없어 컴파일·타입 분석·위 테스트 실행·앱 빌드·실기기 확인을 하지 못했다. 정적 parser 통과는 컴파일 성공이 아니다.
- 구형 새 시즌/영업 초기값·환생/기존 권리·6구 익힘/제품 보관·계정/기기 간 로컬 재화 권위·서버 판매 증거·광고 SDK/개인정보 등 비수치 정책은 그대로 미정이다.
- 새 순수 계산을 바로 유료 구매/광고 지급/영업·재고 전체 흐름으로 연결하면 미승인 정책을 암묵 채택할 수 있어 연결하지 않았다. 이러한 선행과 실행 검수가 남아 해당 작업은 완료로 올리지 않는다.

기존 지갑·상품 ID·구매 토큰·Firestore 규칙·계정·실제 데이터는 변경하지 않았다. 소스/테스트 작성 범위는 정적 검증 후 체크리스트에 근거로 남기고, 후속 정책/실행 가능 환경에서 나머지를 재개한다.
