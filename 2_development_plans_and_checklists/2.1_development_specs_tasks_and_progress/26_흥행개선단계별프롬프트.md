# 26. 흥행 개선 단계별 프롬프트

작성 2026-11-17. "이 게임을 성공적인 게임으로 만들려면 어떻게 개선해야 할까?"라는 질문에 대한 개선안 7가지를 실제 작업 순서로 나눈 지시문이다. 각 단계의 프롬프트를 **새 Claude Code 세션**에 그대로 붙여 넣는다. 한 단계가 완료 기준을 통과한 뒤 다음 단계로 넘어간다.

## 개선 방향 (2026-11-17 제안, 1단계에서 사용자가 확정)

| 번호 | 개선 방향 | 이유 |
| --- | --- | --- |
| 가 | **처음 5분 단순화**: 첫 판은 "굽기 → 팔기 → 칭찬"만. 다른 시스템은 레벨에 따라 하나씩 소개 | 두 재화·숙련 3조건·익힘 5단계·신선도·6구·주문·스킬·손님 관계가 처음부터 한꺼번에 보이면 힐링 게임 이용자는 금방 그만둔다 |
| 나 | **직접 굽기 손맛 극대화**: 판정 연출, 소리, 김·반짝임, 손님 반응, 결과물의 작은 차이 | 짤주머니 색칠·원 그려 뒤집기가 다른 게임과 구별되는 무기이고, 그 장면이 그대로 홍보 영상이 된다 |

| 마 | **매일 돌아올 이유**: 손님 이야기 조금씩 공개, 오늘의 특별 주문, 계절 행사 | 다시 오는 비율이 수익보다 먼저다 |
| 바 | **자연스러운 공유**: 내가 구운 붕어빵·가게 장면 카드 저장·공유(보상 없음) | 홍보비 없이 퍼질 수 있는 유일한 통로. `share_plus`는 이미 들어 있다(`lib/invite_sharing.dart`) |
| 사 | **범위 줄여 12월 출시**: 완성도 높은 구간만 먼저 내고 나머지는 업데이트로 | 붕어빵 철(11~2월)을 놓치면 가장 큰 홍보 기회가 사라진다. Play 비공개 테스트 14일이 필요하다(DEC-030) |

1단계(2026-11-18)에서 가~바는 모두 하기로 했다. 다만 **라**는 자체 서버 집계 대신 Firebase Analytics로(DEC-045), **사**는 "12월 출시·범위 축소" 대신 **날짜 없음·완성도 우선, Lv.50 전체 유지**로 바뀌었다(DEC-042·050). 아래 "확정한 결정" 표가 기준이다.

### 손님 방문·알림 결정 (2026-11-18 사용자 확정)

배경: 지금은 손님이 15초마다(`ordinary_sale.customer_arrival_interval_ms` 15000) 오고 줄 3명(`max_queue`)이 늘 차 있으며, 5분(`order_wait_ms`)을 기다려서 "손님이 너무 많이 온다"는 의견이 나왔다. 판매 붕어빵력(1개 20·40·60)은 자동 생산에 비해 작아 손님 수를 줄여도 성장 속도는 거의 그대로다. 대신 희귀 황금과 레벨업 '추가 판매'(레벨당 1~5번, Lv.50까지 합계 145번)가 판매 수에 묶여 있다.

| 항목 | 결정 |
| --- | --- |
| 시간 기준 | **실제 시간**. 앱이 꺼져 있어도 흐른다. 켜 있을 때와 꺼져 있을 때 간격이 같다 |
| 일반(무기명) 손님 | **1~15분** 사이 무작위 간격으로 한 명 |
| 네임드 손님 | **30분~3시간** 사이 무작위 간격으로 한 명. 일반 손님과 타이머가 따로 돈다 |
| 기존 70:30 확률 | 쓰지 않는다. `anonymous_visit_basis_points`(무기명 30%)는 두 간격으로 대체 |
| 꺼져 있을 때 쌓이는 손님 | 일반 최대 **3명**, 네임드 최대 **1명** |
| 손님 기다림 5분 | 앱을 **켠 순간부터** 센다(꺼져 있는 동안 온 손님이 들어오기 전에 떠나지 않게) |
| 네임드 고르기 | **하루 1회 제한(`visits_per_npc_business_day`) 없앰**. 대신 **바로 앞에 온 네임드는 빼고** 무작위. 만난 사람이 1명뿐이면 그 사람 |
| 새 네임드 소개 | 지금 규칙 유지: 네임드 차례에 못 만난 사람이 있으면 먼저 소개, 하루 최대 2명(`new_npcs_daily_limit`), 도윤부터 |
| 튜토리얼 | 첫 손님 도윤은 바로 등장. 튜토리얼이 끝날 때까지는 필요할 때 손님이 바로 온다(지금 방식) |
| 영업과 자정 | 영업을 열어 두면 **자정(KST)이 지나도 손님이 계속 오고, 영업일은 자동으로 다음 날로 넘어간다**(지금은 '영업 시작'을 다시 눌러야 함). 영업을 닫으면 손님이 오지 않는다 |
| 알림 방식 | 앱이 꺼져 있을 때 손님이 오면 알림. **기기 안 예약 알림**(서버 푸시·Firebase 메시징 쓰지 않음. 1장 원칙: Firebase는 core/auth/functions만) |
| 알림 종류 | 일반 손님 알림과 네임드 손님 알림을 **설정에서 따로** 켜고 끈다. 일반은 **올 때마다**(최대 3번), 네임드는 이름을 넣어서(예: '도윤이 찾아왔어요') |
| 알림 권한·기본값 | **튜토리얼이 끝난 뒤** 한 번 묻는다. 기본값 **네임드 켬, 일반 끔** |
| 밤 알림 끄기 | 설정 하나. **밤 10시~아침 8시**(기기 시간) 알림을 보내지 않는다. 손님은 그대로 온다. **기본 켬** |
| 복귀 보고 | 다시 들어왔을 때 보고에 '자리 비운 동안 손님 N명이 왔어요' 추가 |
| 판매 붕어빵력 | 그대로 둔다 |
| 희귀 황금 확률 | **3배**: 별점 1~5성 1·2·3·4·5% → **3·6·9·12·15%** (`rare_gold_sale.probability_basis_points_by_stars` 100~500 → 300~1500). 하루 최대 10개 유지 |

## 사용 팁
