# 29. 친구 초대 설계 (정식 출시용)

작성 2026-11-24 · 근거 결정 [DEC-150·151·152](2.1.1_game_rules_and_decisions/00_결정취합.md) · 상태: **설계안, 구현 전**

가출시에서는 DEC-029대로 랭킹·친구·초대를 숨긴다. 이 문서는 정식 출시 전에 친구 초대를 새 게임에 다시 연결하기 위한 설계다. 표기: **[확인]** 코드·문서에서 확인한 사실, **[추천안]** 확정 전 제안(사용자 결정 필요).

## 1. 지금 상태 [확인]

| 부분 | 지금 | 문제 |
| --- | --- | --- |
| 서버 (`firebase/functions/src/invites.ts`) | 초대 코드(`BB`+8자), 초대권(ticket), 수락(`inviteAccept`), "Lv.1 도달" 사건 기록(`reachedLevelOne`), 사건 목록. 신규 판정은 계정 생성 24시간 이내 | 사건만 기록하고 보상은 주지 않는다 |
| 앱 보상 (`invite_controller.dart`, `invite_config.dart`) | 앱이 사건을 받아 **코인**(신규 5·기존 2)을 계정 쪽 예전 지갑에 넣는다 | 코인은 예전 클리커 화폐(28번 C3에서 화면 정리). 수치는 `inviteEvidence = 'estimated'`, 다른 게임 공략 글을 근거로 한 추정값 |
| 레벨 조건 (`online_controller.dart` `syncOnline`) | 계정 쪽 예전 레벨 `GameState.level >= 2`일 때 `inviteReachedLevelOne` 호출 | 예전 레벨은 이제 오르지 않아(예전 자동 레벨업 꺼짐) **절대 충족되지 않는다** |
| 화면 | 초대 `InvitePanel`·친구 `FriendsPanel`·랭킹 `RankingPanel`은 남아 있고 테스트(`stage9_ranking_test`)도 있음 | 새 홈에 입구가 없다(예전 홈에서만 열렸음) |
| 친구 방문 | 서버 방문 기록, 앱이 2분마다 `fetchVisits`로 받아 손님으로 보여 줌(계정 시계 `tick`이 동기화) | 새 홈의 손님 체계(WorkshopController)와 연결 여부 재확인 필요 |

## 2. 목표 동작

1. 메뉴의 '친구 초대'에서 내 초대 코드와 공유 버튼을 본다. 공유는 Play 스토어 링크(초대 코드·초대권 포함)를 보낸다.
2. 친구가 설치하고 첫 실행 로그인을 마치면 초대가 수락되고 서로 친구가 된다(지금 서버 규칙 유지).
3. 초대받은 친구가 **새 게임에서 목표 레벨**에 오르면 초대한 사람이 **황금**을 받는다. 지급은 서버가 한다.
4. 초대받은 친구도 시작 선물을 받는다 [추천안].

## 3. 보상 [확정 DEC-151, 2026-11-24 추천안 그대로]

황금 규모 [확인]: 첫 가입 환영 10개(`welcome_reward`), 보상 광고 1회 1개·하루 2회(`rewarded_ads`), 출석 7일마다 1개, 가장 작은 충전 60개(`catalog.json` `gold_60`), Lv.11 레벨업 20개.

| 항목 | 추천안 | 이유 |
| --- | --- | --- |
| 초대한 사람 | 친구 1명이 **Lv.5** 도달 시 황금 **5개** | Lv.2보다 높여 가짜 계정으로 채우기 어렵게. 광고 2~3일치 수준 |
| 초대받은 사람 | 수락 시 황금 **3개**(환영 10개에 더해) | 초대받아 들어온 보람. 너무 크면 계정 돌려막기 동기가 됨 |
| 한도 | 초대한 사람 기준 **하루 3명·평생 20명**(평생 최대 100개) | 가장 작은 충전 상품(60개)을 넘는 무한 수급을 막음 |
| 지급 위치 | **서버 지갑**(`wallet.ts`)만. 앱은 결과를 다시 읽기만 | 황금은 결제와 같은 지갑. 앱 지급은 위·변조 위험 |

## 4. 악용 방지 [추천안]

- 신규 판정: 지금처럼 계정 생성 24시간 이내 + 초대받은 계정당 1번만.
- 목표 레벨 도달은 앱 신고가 아니라 **서버가 가진 진행 증거**로 확인한다. 이미 있는 서버 타당성 검증(`plausibility_validator.ts`, 레벨·판매 진행을 서버 시간으로 제한)을 같이 쓴다.
- 같은 기기 반복 가입: App Check(Play Integrity, 23번 7단계)를 통과한 요청만 받는다. 기기 식별자는 쓰지 않는다(광고 ID·SSAID 수집 금지 원칙 유지).
- 자기 초대(같은 계정·같은 로그인 공급자 ID) 거절, 하루·평생 한도는 서버 트랜잭션으로.
- 지급은 사건 ID 기준 1번만(지금 `eventId` 규칙 유지, 원장 중복 방지).
