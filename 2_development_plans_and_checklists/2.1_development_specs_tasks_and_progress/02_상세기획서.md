## 최신 확정 반영 — 2026-10-16

10월 15일 [사용자 답변 기록](2.1.1_game_rules_and_decisions/00_결정취합.md)의 첫~세 번째 답변이 이전 미정/추천 문장보다 우선한다. 팥 미디엄 레시피만 기본 지급하고 구매 없이 핵심 진입한다. 다른 익힘은 직접 만들어 수집하며 해당 익힘의 선구매를 요구하지 않는다. 숙련은 맛별이고 **연습5종 수집 AND 인정 연습량 AND 손기술 통과량**을 모두 요구한다. 저장 확정된 실패 완주 연습은 연습량에 포함, 주문 제작은 수집만 인정한다. 초기 숙련/6구/도감완성을 선지급하지 않는다. 덜 익음은 특별 주문 판매 가능이며, 6구 수확/제품 보관은 여전히 다음 질문 대기다. 최종 단계 명칭·미디엄 대응·손기술 세부 기준·횟수·가격·확률·광고량은 새로 확정하지 않는다.

[선행 작업별 대조와 복구 설계](12_선행기획검토와복구설계.md)를 함께 읽는다. 아래 구형 설명에서 실패 인정·주문 반영·5종 관계를 통째로 미정이라고 표현한 부분은 이 확정 범위로 한정해 읽는다. 코드/데이터 이전·실행 검수는 하지 않았다.

## 1. 콘셉트와 성장 흐름

힐링 붕어빵 제작·수집·가게 운영 게임이다. 핵심은 **레시피 획득 → 맛별 큰 틀 연습 → 숙련/해당 도감 완성 → 6구 생산 해금 → 직접 수확해 재고 준비 → 주문 대응·손님 취향 수집**이다. 숙련 전에도 보유 레시피로 즉석 제작·판매할 수 있다. 큰 틀은 연습과 즉석 대응,6구는 사전 재고 준비를 맡는다. 무조건 많이 만들기보다 수요·대기·신선도를 고려한다.

### 기능 진입·상품·숙련 게이트

초기 꾸미기는아바타분류만제공한다. 나머지꾸미기·각도감·친구의기능진입은해당해금레벨을요구한다. 정확레벨/순서는미정이며조건/안내/접근차단을상태별로표현한다. 기능개방이아이템무료지급이나맛숙련완료를뜻하지않는다. 도감UI가잠겨도연습→숙련→6구진행을막지않도록기록/접근을분리설계하며해금전기록인정/표시정책은결정한다.

### 상점/스킬 복합 구매와 판매 황금 보상

상점상품/스킬은항목별붕어빵력AND황금붕어빵력비용을같이요구한다. 견적에두가격/잔액/부족사유를보이고한쪽부족이면최종구매/차감하지않는다. IAP충전은실제결제이며상품구매의두재화가격과구분한다. 구매회차/묶음증가·금액은미정이다.

판매완료시드물게황금붕어빵력보상. 만족도는별5개만점이며손님요구에잘맞아만족도가높을수록드롭확률이높아진다. 5점확정지급/확률표/수량/가중치는추정하지않는다. 판매ID·별점·판정버전·추첨결과/서버지급상태를연결해재시도로재추첨/중복지급하지않는다. 일반판매대금과는별도다. 상세프로토콜/적용판매/오프라인보상은 [경제 계약](10_복합경제와50레벨해금.md)에결정필요로남겼다.

### 선택형 광고의 황금 보상

황금획득영역에사용자선택시청과오늘남은횟수를표시하는안을둔다. 정상보상시청은하루최대2회,황금지급량/업체/SDK/정확UI/해금레벨은미정이다. 광고닫힘과보상완료를구분하고로드실패/중도종료에허위지급/소진확정하지않는다. 지급확인대기·재시도·동기화와일일슬롯을연결해중복/세번째지급을막는다.

광고는판매만족도희귀추첨과별도이며주문성공/숙련/재고를생성하지않는다. 광고중손님대기/큰틀/6구의시간처리는미정이고영업종료로자동처리하지않는다. 정확한일일경계/비로그인정책·검증·광고예외는 [일2회광고](11_하루2회보상형광고.md)를따른다.

## 3. 레시피 획득과 숙련

팥은 기본 보유하지만 초기 숙련/도감 완성/6구 해금은 주지 않는다. 슈크림·초코 등은 상점 **OR** 지정 미션으로 간헐 획득한다. 레벨마다 자동 지급하지 않는다. 맛별 상점/미션 개방 조건은 별도이며 레시피를 이미 얻은 뒤 큰 틀 제작에 추가 레벨/누적 조건을 붙이지 않는다.

| 관리 정보 | 의미 |
| --- | --- |
| 레시피 획득 여부 | 제작법을 획득했는지 |
| 제작 연습 방식 | 해당 맛에서 수행할 연습과 판정 규칙 |
| 요구 연습량/현재 진행량 | 맛별 필요량과 인정된 누적 진행 |
| 숙련 완료 조건/달성 여부 | 요구 연습량 **AND** 해당 맛의 나머지 지정 조건을 모두 충족했는지 |
| 도감 완성 여부 | 맛의 정식 완성. 단순 발견·첫 제작과 별도 |
| 6구 생산 해금 여부 | 해당 맛 숙련을 완료했는지. 보유 **AND** 숙련 완료가 무작위 후보의 필요조건 |

실패 완주 연습 포함·주문 제작은 수집만·연습5종 AND 연습량 AND 손기술 조건은 확정이다. 구체 횟수와 손기술 판정은 DEC-015 미정이다. 데이터/UI/검수에서 이 관계를 고정하지 않는다. 숙련 조건 전체 충족과 도감 완성·해금은 하나의 확정 처리로 일관되게 반영한다.

## 4. 큰 틀 제작과 판매

종류 선택→첫 반죽→방향 입력으로 숟가락 굴리기/젓가락 속 넣기→둘째 반죽→뚜껑→뒤집기→굽기→터치 꺼내기→결과 순서를 유지한다. 기울기 입력과 동등한 누름 붓기·방향 버튼 등 터치 대체를 제공한다. 맛마다 다른 연습 방식·요구 연습량을 적용하되 세부 레시피 표는 미정이다.

손님별 반죽·속·익힘 선호를 표현할 수 있게 주문 맥락과 레시피 연습 목표를 분리한다. 앞선 요구의 반죽/속 취향을 보존하되 정확한 항목 수·목표량·허용 범위·만족도 관계는 확정하지 않는다. 연습용 제작과 주문용 제작을 구분하고 주문용을 연습 진행에 자동 합산하지 않는다.

**레시피가 있으면 숙련 전후 모두 큰 틀에서 즉석 제작·판매할 수 있다.** 즉석 판매를 허용한다는 확정은 일반 연습 결과마다 재고+1을 준다는 뜻이 아니다. 연습 산출물 보관·즉석 제품의 재고 경유 여부·판매대금은 DEC-004에서 정한다. 결과·판매는 고유 처리 ID와 원자 저장으로 중복 지급/납품을 막는다.

포인터 취소/단계 이탈은 지속 입력을 중단하고 이전 제스처를 다음 단계로 전달하지 않는다. 저장 실패는 동일 판정으로 재시도한다. 주문용 제작 중에는 손님 대기시간이 계속 흐르므로 기존 ‘제작하면 모든 시간을 정지’ 초안은 적용하지 않는다. 앱 이탈 중 제작/손님 시간 정책은 DEC-006/017이며, 영업 상태와 붕어빵력 생산 지속은 별도로 확정이다.

## 5. 익힘5단계와 붕어빵 도감

| 임시 단계 | 임시 명칭 | 표현 요구 |
| --- | --- | --- |
| 1 | 덜 익은 | 다른 단계와 색·모양 구분 |
| 2 | 부드럽게 익은 | 동일 |
| 3 | 노릇하게 익은 | 동일 |
| 4 | 바삭하게 익은 | 동일 |
| 5 | 타버린 | 동일 |

5단계 구성은 확정, 이름은 임시안이다. 과거 초기 반죽을 포함한7단계 표·10초 경계·알맞음/노릇함만 성공이라는 제안은 현 판정으로 재사용하지 않는다. 제작 도중의 반죽 상태는 연출 상태일 수 있지만 여섯 번째 수집 단계로 만들지 않는다.

도감은 **레시피×익힘**이다. 연습 중 발견 기록과 진행량을 보여주되 정식 등록/완성과 구분한다. 요구 연습량을 모두 채우기 전 해당 맛을 완성하지 않는다. 연습5종 수집은 숙련의 필수조건이며 주문 수집으로 대체하지 않는다. 익힘별 세부 등록 조건·판정 임계·완성 보상은 미정이다. 판매나 재고 소멸로 영구 발견/완성 기록을 역산하지 않는다.

## 6. 6구 생산과 직접 수확

처음 보유 레시피는 팥뿐이며 **팥도 숙련 후** 생산한다. 보유 AND 숙련한 맛이 없으면 제품 후보가 없다는 상태를 안내한다. 이후 획득하고 숙련한 맛만 무작위 후보에 추가한다. 칸은 각기 다른 타이밍으로 천천히 익는 기존 방향을 유지한다.

수확하지 않은 제품은 재고가 아니다. 플레이어의 유효 수확 입력으로 확정할 때만 재고 반영한다. 오프라인 자동 수확·재고 지급은 금지다. 같은 칸 중복 입력과 실패 재시도는 한 회차의 같은 결과로 처리한다.

무작위 후보 조건은 확정이나 **칸별 레시피 지정/무작위 배정 방식·생산 주기·익힘 선택 방식·수확 대기 처리**는 DEC-011 미정이다. 랜덤의 균등 확률·순환·칸배율·재투입1.5초·자동 폐기·재시작 초기화·특정 익힘의 지급 수를 확정하지 않는다. 황금 찬스와 입력 충돌도 결정 대상이다.

## 7. 손님 도감과 취향

손님 이름·외형·특성, 좋아하는 레시피, 좋아하는 익힘, 취향 발견/도감 진행 상태를 관리한다. 현재 주문은 이번에 필요한 제품이고 지속 취향은 손님의 선호 기록이다. 한 번 주문했다고 그 맛/익힘을 영구 취향으로 확정하지 않는다.

주문·판매 경험과 취향 발견을 연결하되 취향 개수·발견 조건·힌트·취향 일치 보상·도감 완성 보상은 DEC-016 미정이다. 요구충족 기반 판매 만족도(최대별5개)와희귀황금확률상승은확정이나취향/신선도영향과가중치는별도미정이다. 반죽/속 선호는 앞선 요청대로 표현 가능하게 설계하되 구체량을 생성하지 않는다.

## 8. 주문·줄 대기·두 대응 수단

첫릴리즈만렙은50이며레벨이오를수록요구맛종류와수량이증가한다. Lv.1~50의성장/주문/기능해금표는미정이다. 초반 적은 종류/수량, 성장 후 복수 종류/더 많은 수량이라는 방향만 확정이다. 맛별 레벨·수량·최대 방문 인원·개인 제한시간·특정 익힘 필수 주문 등장 시점은 미정이다.

손님은 줄에서 기다릴 때에도 자기 대기시간을 소모한다. 뒤 손님은 앞 주문 처리 동안 남은 시간이 줄어드는 구조다. **뒤 순서라는 이유로 초기 제한시간을 추가 차감하는 규칙은 미정**이다. 주문용 즉석 제작 중에도 개인 시간이 소모한다.

재고 판매는 주문 조건에 맞는 신선도별 묶음을 선택해 즉시 제공하고, 즉석 판매는 보유 레시피로 큰 틀에서 필요한 제품을 만든다. 둘을 함께 쓸 수 있지만 이는 부분 납품을 자동 허용한다는 뜻이 아니다. 부분 납품·실패 페널티·현재 주문과 취향의 관계·추가 판매·일반 판매 대금과 희귀 황금 보상 세부값은 결정 대상이다. 생산 해금 전 맛의 즉석 주문도 숙련 미완료만을 이유로 막지 않는다. 주문 생성 가능 맛의 구체적인 필터는 결정한다.

## 9. 제작일별 재고·신선도

제품은 맛·익힘뿐 아니라 제작 영업일별로 구분한다. 같은 조합이라도 다른 날의 제품은 별도 묶음이다. 제작 당일0일, 실제 영업한 새로운 날짜마다 나이+1, **나이5영업일 이상이면 제거**한다. 소멸은 납품에서 제외하며 반복 정산으로 두 번 제거/보상하지 않는다.

월요일 제조0→화요일 영업1→수~금 미접속→토요일 영업2다. 현실 날짜 차이를 빼서 나이를 계산하지 않는다. 같은 날짜 재접속·재영업은 그대로다. 단순 접속만으로 나이를 올리지 않는다.

신선도별 판매가·만족도·오래된 재고의 판매 가능 범위·할인·자동 판매 우선순위는 DEC-018 미정이다. 준비 중/영업 시작 전 제조분의 제작 영업일 귀속도 결정해야 한다. 선입선출·가격 감소율·창고 상한·소멸 보상은 임의 추가하지 않는다.

## 10. 영업 시작·영업일·앱 종료

접속과 실제 영업 시작을 구분한다. 같은 날짜의 여러 영업은 하나의 영업일이다. 미접속/미영업 날짜는 신선도 경과에 포함하지 않는다. 새로운 날짜의 실제 영업을 인정할 때 영업일 증가와 재고 노화를 함께 처리한다.

영업 중 종료 후 다음 날짜 복귀 시 영업일 증가 시점, 날짜 경계시각/시간대, 영업 종료 방식은 DEC-019 미정이다. 오전5시·자정·접속 즉시 증가를 확정하지 않는다. 기존 일일/주간 미션의 KST 자정 규칙을 영업일에 자동 복사하지 않는다. 앱 종료만으로 영업 종료하지 않는다.

## 11. 영업 중 붕어빵력과 오프라인 정산

| 상태 | 붕어빵력 자동 생산 | 제품 재고 |
| --- | --- | --- |
| 영업 시작 전 | 없음 | 자동 지급 없음 |
| 영업 중·전경 | 기존 생산 계산을 영업 상태로 게이트 |6구는 직접 수확해야 반영 |
| 영업 중·앱 종료 | 복귀 시 미정산 시간에 기존8시간 상한·50% 효율 적용 | 자동 수확/지급 없음, 현실 공백 노화 없음 |
| 영업 종료 | 없음 | 실제 영업일 인정 외 노화 없음 |

붕어빵력은상점/스킬에서황금붕어빵력과함께지불한다. 각비용·최대보유량·일반판매대금통화는미정이다. 판매황금희귀보상의발생/만족도방향은확정이나수치/검증주체는미정이다. 자동 속도는 현재 코드/기존 밸런스 초안을 구분하고 [성장안](07_성장난이도.md)을 따른다.4시간 제한은 도입하지 않는다.

이탈/복귀 기준시각·영업 상태·정산 완료 구간·재화/나머지를 한 저장 단위로 관리한다. 같은 구간 재접속/재시도로 중복 지급하지 않는다.8시간 초과분을 다음 복귀에 뒤늦게 지급하지 않도록 정산 기준을 전진시키는 기존 원칙을 유지한다. 영업 종료 명령은 종료 직전까지 한 번 정산한 뒤 생산을 중단하도록 기술 설계한다. 완료된 판매와 도감 기록은 실패 시 재고/진행과 함께 복원한다.

## 12. 배경·오디오·기존 시스템

배경과 명시 BGM 선택은 독립 저장한다. auto 허용/이전 기본은 기존 후보로 남긴다. BGM·굽기 루프·일반 효과음은 별도 켜기/볼륨/수명이며 비활성 시 실제 출력·센서를 중단한다. **영업 중 오프라인 생산은 오디오가 계속 재생된다는 뜻이 아니다.** 새5단계 익힘에서 굽기 활성 범위를 다시 결정한다.

코인·기존소유/보상·부스트/랭킹·유료상품/지갑은보존하되복합구매·판매황금·50레벨새시즌·친구기능잠금으로확장한다. 코인구매경로와환생정책은재결정대상이다. 환생이 새 숙련/영업/재고/취향에 미치는 영향은미정이다. 기존 방문/초대 손님 연출을 새로운 주문/손님 도감으로 구현되어 있다고 간주하지 않는다. 판매황금지급검증에필요한판매ID/만족도근거/결과의최소서버계약을설계한다. 손님도감전체를무조건전송하거나추적SDK를추가하지않는다.

## 13. 검수·인계

[통합 검수 기준](09_통합검수기준.md)에 최신 확정 규칙과 미정 기대값을 구분했다. 저장·시계·중복 명령·신선도 경계·숙련 전 판매·줄 대기·영업 종료/복귀가 필수다. 모든 게임 검수는 미실행이다. 일정·작업은 [원장](tasks.json)과 [단계 문서](README.md)로 연결하고 새 범위의 시간은 재산정한다.
