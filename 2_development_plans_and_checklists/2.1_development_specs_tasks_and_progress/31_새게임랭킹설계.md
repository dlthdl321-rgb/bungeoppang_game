# 31. 새 게임 랭킹 설계와 결과 (정식 출시용)

작성 2026-11-25 · 근거 결정 [DEC-153](2.1.1_game_rules_and_decisions/00_결정취합.md) · 상태: **구현 완료(출시 스위치 꺼 둠), 2026-11-25**

예전 랭킹은 예전 클리커 값(최고 초당 생산·누적 붕어빵·콤보)을 앱이 보내고, 서버는 "너무 빨리 늘지 않았나"만 봤다. 새 게임에서는 그 값이 오르지 않고, 앱이 보내는 점수는 고쳐 보낼 수 있다. 그래서 새 게임 랭킹은 **서버가 이미 검증해 둔 진행 기록에서 점수를 읽는다.**

## 1. 판

| 판 | 점수 | 출처 |
| --- | --- | --- |
| `workshopPieces` 판매왕 | 손님에게 판 붕어빵 개수 | 서버 진행 확인 기록(`users/<uid>/workshopPlausibility/<진행ID>`)의 `pieces`(옛 앱은 `sales`) |
| `workshopLifetime` 누적 붕어빵력 | 지금까지 만든 붕어빵력 | 같은 기록의 `lifetimeBuns`(최대 2^63−1) |

- 진행 확인 기록은 구매·보상 신청 때 서버 시간과 스킬 효율로 검사를 통과한 값만 남는다(`plausibility_validator.ts`). 그래서 랭킹 점수도 그 검사를 통과한 값이다.
- 점수는 줄지 않는다(다른 기기의 예전 진행으로 바뀌어도 최고 기록 유지).
- 같은 사람의 요청은 1분 간격 이상(`rankingSubmitMinGapMs`).

## 2. 앱

- 온라인 동기화(2분마다) 때 `rankingWorkshopSubmit`을 부른다. 앱은 점수를 보내지 않는다.
- 새 홈 메뉴 '온라인 랭킹': 두 판(판매왕·누적 붕어빵력) 상위 100명과 내 순위. 기존 `RankingPanel`을 판 목록을 받게 고쳐 다시 쓴다.
- 출시 스위치 `rankingLaunched`(지금 false). 가출시는 숨긴다(DEC-029).

## 3. 진행 기록

- 서버: `ranking.ts` `submitWorkshop`·새 판 이름, `index.ts` `rankingWorkshopSubmit`, 테스트 `ranking.test.ts` +1 — 완료
- 앱: `ranking_config.dart` 새 판 이름·출시 스위치 `rankingLaunched`(false), 동기화 때 `rankingWorkshopSubmit`(`online_controller.dart`), `RankingPanel(boards:)`, 새 홈 메뉴 '온라인 랭킹'(`workshop_page.dart`). 테스트 `workshop_shared_ui_test`(메뉴·두 판), `premium_flow_test`(스위치 켜야 기록 요청) — 완료
- 정식 출시 때: `rankingLaunched`를 true로, 서버 배포(`rankingWorkshopSubmit`)
- 예전 판(`bestAutoRate`·`lifetime`·`bestCombo`)과 `rankingSubmit`은 예전 클리커 코드 정리(DEC-155) 때 지운다.
